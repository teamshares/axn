# Changelog

## Unreleased

### Added

* [FEAT] `Axn.config.on_ignored_exception` reports the exceptions axn swallows in its side channels, which until now were visible only as a log line. An `on_success` callback that raises, an observability facet resolver, a custom `validate:` block, a failing tracer — all run inside a `best_effort` guard so they cannot break the action, and their failures never reach the result: `result.ok?` is usually `true`, nothing downstream can observe them, and the side effect they were meant to perform silently did not happen. **By default they now route to whatever `Axn.config.on_exception` is configured with**, so an app that already reports exceptions starts receiving these with no wiring — expect new (genuine) reports on upgrade. Assign a callable to send them elsewhere, or `false` for the previous log-only behavior. The exception is passed unwrapped (so error-tracker grouping keys on the code that actually raised) and carries a `context[:axn_ignored]` key that an ordinary `on_exception` report never has: `while:` names what was being attempted, and `outcome:` gives the surrounding action's outcome as a severity signal — `"success"` is the alarming case (caller got their result, side effect vanished), a failed outcome is collateral to a failure already being reported. `outcome:` is omitted rather than guessed when the action has not settled yet (many guards fire mid-run) or when there is no action to ask, so branch on its presence. A failing `on_exception` handler is deliberately not re-reported through itself — useless when it is persistently broken, and an amplifier against a merely degraded provider — and a handler that runs an Axn action of its own cannot re-enter itself (see PRO-3139).
* [FEAT] `forward!` delegates to a sub-action and propagates both its exposures and its outcome, collapsing the documented facade idiom (`r = Child.call(**inputs); expose(r); raise r.exception unless r.ok?`) to one line. Pass a class to invoke it with `**inputs`, or a result you built yourself. Non-terminal: on success it returns the sub-action's result and execution continues. On any non-ok outcome it settles this action exactly as the `call!` it replaces would — same error string, and `result.exception` is the sub-action's own exception object, so conditional `error ..., if: SomeError` handlers still match. It is also the only way to get exposure forwarding from the `call!` shape, where the raise leaves `#call` before any `expose` can run (see PRO-2941).
* [FEAT] `of:` declares a map's contents on a `type: Hash` field: `of: { keys: Symbol, values: Integer }` validates every key and every value. Either axis may be omitted, which leaves that axis unconstrained — `of: { values: Integer }` accepts any key. An axis you write has to name a type: `values: []`, `values: nil` and `values: false` all raise at declaration rather than passing as a constraint that matches nothing (a non-class token previously reached `value.is_a?(false)` and raised a bare `TypeError` on every call), and `of: {}` raises on the same rule. The refusal names **the axis you wrote** and the defect it actually has, in the same words a bag's `klass:` uses for the identical mistake: `of: { values: [] }` reports "of: values: names an empty union, so that axis constrains nothing", not a request to name an axis that is already there, and `of: { keys: Symbol, values: [] }` reports the emptiness rather than "must name a type" — `[]` *is* the union spelling. The "name the axis you are constraining" refusal is now reserved for the bag that has nothing to point at — **both** axes absent or `nil`. Every other pair names an axis you wrote and reports the defect that axis actually has: `[]` gets the empty-union refusal (including beside a `nil` sibling), and a `nil` or otherwise non-class axis beside a sibling that *was* written gets `of: <axis>: must name a type … (got a value of class NilClass)`. All 36 axis-pair combinations are pinned as a truth table in `of_validator_spec.rb` (see PRO-3170). Each axis takes the same forms `type:` does: a class, a union array, the `:boolean`/`:uuid`/`:params` symbols, or a `Data.define` class. The bare form (`of: Foo`) stays Array-only and raises on a Hash, since a bare class can't say which axis it constrains. A failing entry is reported by its ordinal position (`key at index 0 is not a Symbol`, `value at index 0 is not a Integer`), never its key — a validation message settles unredacted, and rendering the key would leak a `sensitive:` map's own data into `result.exception.message` and the logged line. Reflects in the schema as `additionalProperties` (a union `values:` axis as `anyOf`, a `Data` `values:` class as `properties`); `keys:` emits nothing, since every JSON object key is already a string. A subfield (`on:`) rooted at a map, at any depth, is refused as "not supported yet" (see PRO-3165); `of:` beside `shape:` on a Hash was refused with it, and is granted below by PRO-3166.
* [FEAT] `of:` recurses: the bag naming a container's contents may name a container of its own, at any depth. `of: { klass: Array, of: Integer }` describes an array of arrays, `of: { values: { klass: Hash, shape: ... } }` a map of shaped records — the last gap in the declaration grammar, a container sitting directly inside a container with no member name to hang the next level on. One **inner-contract bag** in three positions — an Array's element, a map's `keys:` axis, a map's `values:` axis — each carrying `klass:` / `of:` / `shape:` / `message:`; a bare class in any of them is still sugar for `{ klass: <that class> }`. Inside a bag, `klass:` plays the role `type:` plays at the top level: it names the value's class *and* decides which grammar that bag's own `of:` is held to (`klass: Array` takes an element contract, `klass: Hash` a `keys:`/`values:` pair), which is what makes the recursion one rule rather than two. A `shape:` at an **axis** takes the same raw form the field-level option does, so its `members:` are objects answering `field`/`validations` — a `Struct.new(:field, :validations)` is enough — since no block form reaches an axis: a block written beside `of: { values: ... }` attaches to the field's own shape and buys the exemption below instead. A bag now only has to constrain **something** — at least one of `klass:`, `of:`, `shape:` — so `of: { shape: ... }` constrains an element's members while leaving its class open; `of: {}` and `of: { message: "..." }` still raise, since a message describes a constraint rather than being one, and a bag whose `of:` has no container to be read against raises too (`of: { of: Integer }` names none, `of: { klass: String, of: Integer }` names something with nothing inside it, `of: { klass: [Array, Hash], of: ... }` names two grammars at once). A per-axis `message:` is now spellable (`of: { values: { klass: Integer, message: "must be a whole number" } }`), which a bag-level `message:` on a map never could, since one message cannot say which axis failed. Failure messages compose one position per level — `element at index 0: element at index 1 is not a Integer`, `value at index 0: sku is not a String` — and a map entry is still located by its **ordinal, never its key**, at every depth: a validation message settles unredacted, so rendering a key would publish exactly what a `sensitive:` declaration asks to be masked. The schema nests the same way (`items.items`, `additionalProperties.additionalProperties`, `items.additionalProperties`), and each nested rung is charged against the 25,000-property cap by the enumerator that already walks the emitted document. Two things a nested bag does not reflect: a `keys:` bag emits nothing at all (every JSON object key is already a string), so it is enforced in Ruby and appears in no schema, and on **output** an inner bag carrying its own `if:`/`unless:` promises nothing, exactly as a self-gated type does — the input schema advertises it regardless. Those shared options are refused outright on a map **axis** (`of: { values: { klass: Integer, if: :flag } }` raises), the one position a bag is never handed to ActiveModel as a validator entry, so nothing would read them; gate the field instead. Two spellings inside the new grammar are refused rather than given a reading, both at declaration: `of: { klass: Array, shape: ... }`, because `container: Array` on a shape is what the shape validator reads as "distribute over the elements" — the members would describe what is inside each element rather than the element itself, and the schema would publish none of them, so write the nesting you mean (`of: { klass: Array, of: { shape: ... } }`, which emits `items.items.properties`); and a bag `shape:` that declares a member the block beside it also declares, since the two member lists are unioned into one and a shape may not name one key twice — the same refusal a single block gets, now naming both spellings so you know which two declarations collided. A nested bag's option keys are canonicalized exactly as a field's are, at every rung and in all three positions: `of: { klass: Array, of: { "klass" => Integer } }` and the `.with_indifferent_access` form a Rails author hands in declare the same contract the Symbol spelling does, and one option written under both spellings raises rather than silently dropping one of the two. Nesting is bounded by the same budget a `shape:` graph spends: one depth counter across both edges, 64 rungs, with a cycle (`bag[:of] = bag`) refused at declaration (see PRO-3166).
* [FEAT] `shape:` — or a block — beside `of:` on a `type: Hash` field is now supported, where it raised "not supported yet". A Hash is the only container where the two name **different nodes**: `shape:` names specific keys, `of:` names everything else. So a key the shape names is **exempt** from the map contract rather than intersected with it — `expects :metrics, type: Hash, of: { values: Integer } do field :label, type: String end` accepts `{ label: "q3", visits: 120, signups: 4 }`, rejects `{ label: "q3", visits: "lots" }` with `value at index 1 is not a Integer`, and rejects `{ visits: 120 }` with `label is not a String`. That is what JSON Schema means by `additionalProperties` applying only to keys `properties` does not match, so the emitted property carries both halves at one node (`properties` + `required` + `additionalProperties`) and says exactly what the runtime enforces. The intersecting reading was rejected on two grounds: it makes the common case unsatisfiable — `label` would have to be both a String and an Integer, and the whole reason to combine the options is that the named keys differ in type from the rest — and it has no honest JSON Schema spelling, so the document would be looser than the contract. The exemption covers **both** axes: `keys:` emits nothing, so there is no document to contradict, and the symmetric rule stops `field :label` quietly acquiring a symbol-key requirement it never asked for. It matches a string key as readily as a symbol one (`{"label" => "q3"}` is the exempt `label`, not an entry for `of:` to check — string keys being the common shape for JSON input), and the ordinal in a failure message counts every entry, exempt keys included. A subfield (`on:`) rooted at a map stays refused at any depth: the exempt set is the shape's member keys, derived at declaration from the emitter's own key computation, and what a subfield contributes to `properties` (its leaves, a dotted `on:`'s nested keys, a `model:` route's `<field>_id`) is not knowable there (see PRO-3166).

### Changed

* [INTERNAL] Every reflective read of a caller-supplied class's method table now routes through `Internal::NativeMethods` (`declared_instance_method`, `public_instance_method?`, and the new `module_singleton_class`), which binds Ruby's own implementation instead of asking the class. `spec/axn/internal/no_unbound_module_reflection_spec.rb` enforces this going forward — the method-table half mechanically, with a positive control proving the pattern matches each shape it targets; the naming half (`.name`/`.inspect` on a caller's class) is carried by review, since axn has many legitimate such reads on its own objects. `AGENTS.md` now lists the readers to reach for and the `Identity.kind?` precondition each requires (see PRO-3161).
* [INTERNAL] The warning logged when a callback is swallowed now names the callback's phase — `"executing on_success callback"` rather than `"executing callback"`, which was emitted identically for `on_success`, `on_error`, `on_failure` and `on_exception` alike. This is what `on_ignored_exception` reports as `context[:axn_ignored][:while]`, and an `on_success` callback that silently did not run means something very different from an `on_error` one. Adjust any log-based alerting that matched the old literal (see PRO-3139).
* [INTERNAL] Axn's user-facing sugar — `log`/`debug`/`info`/`warn`/`error`/`fatal`, `result`, `inputs`, `expose`, `fail!`, `done!`, `forward!`, `execution_context`, `ambient_context` — is now defined in included modules instead of being written onto the action class via `class_eval`, so a user's own override can reach the original with `super`: `def log(msg) = super("[prefix] #{msg}")` now works, where it previously raised `NoMethodError: super: no superclass method 'log'`. `class_attribute`s (`before_hooks`, `after_hooks`, `around_hooks`, `internal_field_configs`, `external_field_configs`, `subfield_configs`, and axn's other internal registries) no longer leak an unprefixed public instance accessor alongside the class-level one either (see PRO-3062).
* [INTERNAL] A container's contents are now stored inside its `of:` bag at every depth, instead of at a top-level `validations[:shape]`. For an `Array`-typed field declared with a shape, `config.validations` goes from `{ type: ..., of: { klass: Hash, container: Array }, shape: { container: Array, members: [...] } }` to `{ type: ..., of: { klass: Hash, container: Array, shape: { container: Hash, members: [...] } } }` — the shape's `container:` moves from `Array`, meaning "distribute over the elements", to the element's own class, meaning "read members off this element", because distribution is now the bag's job and `shape:` no longer carries two meanings. Public reflection is unchanged: `input_schema` / `output_schema` and `Extensions::Serialization.render` emit exactly what they did, and a `type: Hash` (or `Data`/`Struct`) field's `validations[:shape]` is untouched. A gem reading `config.validations[:shape]` **directly** for an `Array`-typed field now finds nothing there, and should read a container's contents through `Axn::Internal::ShapeGraph.inner_contracts(validations)` — the one enumerator every seam in core uses, returning `[[position, bag], ...]` with `:[]` for an element and `:keys`/`:values` for a map's axes (see PRO-3166).
* [BREAKING] A validator constrains **the value at the position it is declared at** — and `inclusion:`/`exclusion:` now follow that rule on a container-typed field, where ActiveModel's `Clusivity` had been distributing the set over an `Array`'s elements. `expects :tags, type: Array, inclusion: { in: [["a", "b"], ["c"]] }` asks whether the array itself is a member of the set; the elements are constrained at their own position (`of:`), or with a `validate: ->(value) { ... }` callable until the `of:` bag takes value validators. The distributing reading was never opted into: it emitted as `enum` on the array's own node (a schema that rejected every value the runtime accepted), it inverted to nonsense under `exclusion:` — `all?` under a negating caller meant "reject only when EVERY element is forbidden", so `["ok", "bad"]` passed an `exclusion: { in: ["bad"] }` — and it reached only a field-level `Array`, never a map's axis or an element two levels down. **The common spelling of the old behavior now raises at declaration** (see below), so the failure is loud at boot rather than silent at call time — including `expects :roles, type: Array, exclusion: { in: ["admin"] }`, which rejected `["admin"]` before and would otherwise have accepted it silently, since a can-never-match exclusion set enforces nothing rather than rejecting everything. But `Clusivity` keyed off the VALUE being an Array, not the declared type, so a number of spellings change meaning with no error at all, and every one needs an audit. Those that change without an error: a set whose members happen to be arrays; one read dynamically (a Symbol or Proc source, which cannot be judged at declaration); a set axn may not read side-effect-free (an `Array` subclass, or an `ActiveRecord::Relation`), whose contract now accepts nothing while the schema advertises no `enum` at all; an undeclared `type:`; a declared SUPERTYPE (`type: Object, inclusion: { in: ["a", "b"] }` accepted `["a"]` and now rejects it, since the array is no longer taken apart); a union carrying a scalar (`type: [String, Array]`); and any tolerance flag (`optional:`/`allow_nil:`/`allow_blank:`). `inclusion:` on a `type: Hash` field is unchanged — `Clusivity`'s special case was Array-only (see PRO-3192).
* [BREAKING] Two validators are refused at declaration on a field whose every declared type is a container (`Array`, `Hash`, `Set`): `format:`, which ActiveModel matches against `value.to_s` and which therefore constrained the Ruby inspect form (`format: { with: /a/ }` really did accept `["a"]`), and `numericality:`, which accepts no container value at all and so rejected every input. `comparison:`/`acceptance:` are **not** refused by key: they are judged by their literals instead, alongside `inclusion:` (see below). A union type carrying a scalar (`type: [String, Array]`), an undeclared type, a pseudo-type token and a disabled entry (`format: false`) all still declare cleanly. An `if:`/`unless:` gate does **not** excuse either refusal: a gate decides whether a check runs, not what it can mean. Drop the option, or constrain the contents at their own position (see PRO-3192).
* [BREAKING] An `inclusion:`, `acceptance:` or `comparison:` constraint no value of the declared `type:` could satisfy is refused at declaration, at **every** type: `type: Array, of: String, inclusion: { in: ["a", "b"] }` (the old element-wise spelling), `type: Integer, inclusion: { in: ["1", "2"] }`, `type: Array, comparison: { greater_than: 1 }` and `type: Array, acceptance: true` (compared against ActiveModel's own default `["1", true]` set) alike were contracts that rejected every input while looking like constraints. Judged by the runtime's own type matcher, so the refusal cannot disagree with the check it predicts, and it stands down wherever a passing value survives: a contract that admits nil at all — a tolerance flag, a nil-admitting `type:`, or a validator such as `acceptance:` that skips nil of its own accord — judged across every validator on the field rather than per entry, since one entry's tolerance does not carry a field whose other checks still reject nil, an undeclared or pseudo-type `type:`, a comparison/acceptance bound the runtime resolves per call (a Symbol or Proc), a `comparison:` bound on any non-container type at all (outside a container, `<=>` and `==` belong to the declared class — a `Comparable` value object whose `<=>` accepts a `Numeric` satisfies `type: Money, comparison: { greater_than: 0 }`, and no ancestry test predicts that), a `Hash` `accept:` set (`AcceptanceValidator` reads it as pairs, not keys), and any set axn may not read side-effect-free — an `ActiveRecord::Relation` or an `Array` subclass. A `Range` set stands down at a **scalar** position, where cross-type comparison genuinely works (`(1.0..5.0).cover?(3)` is true), but is judged by its BOUNDS at a **container** position, since `<=>` is nil across unrelated classes and `type: Array, inclusion: { in: 1..5 }` can never match. The judgment is a closed world: it reaches only pairs drawn from Ruby's core value types (`String`, `Symbol`, `Integer`, `Float`, `Rational`, `nil`, `true`/`false`, `Array`, `Hash`, `Set`, `Date`, `Time`, `DateTime`) and stands down on every other pair, a SUBCLASS of one of them included — equality is not inferable from ancestry (`SubArray.new([1]) == [1]` and `SubRegexp.new("a") == /a/` are both true, and a `Comparable` value object may accept whatever its `<=>` chooses), so the guard names what it knows rather than enumerating exceptions. Within that set a literal in the same cross-comparable family still compares across classes (`Numeric` with `Numeric`, or the `Date`/`Time`/`DateTime` trio), which is why `type: Float, inclusion: { in: [0, 1] }` declares — but only for an `Array` set, since a `Set` or a `Hash` looks its members up by `hash`/`eql?` rather than `==` and `eql?` never crosses a family (`Set[1].include?(1.0)` is false where `[1].include?(1.0)` is true), so `type: Float, inclusion: { in: Set[1] }` matches nothing and is refused. A `comparison:` entry naming several operators is judged **conjunctively**, as ActiveModel applies it — one unsatisfiable bound sinks the entry, so `type: Array, comparison: { equal_to: ["a"], greater_than: 1 }` is refused though its equality literal is an Array. `comparison: { other_than: ... }` is not judged here: it is an inverted operator, so a wrong-type bound makes the check always pass rather than never — vacuous, not unsatisfiable — the same reason `exclusion:` is not judged here either. Both are refused by the vacuity guard below instead. An `if:`/`unless:` gate does **not** excuse one: reflection is static-maximal, so a gated can-never-match set would still emit an unsatisfiable node, and a gate removes the check rather than giving the set a reading (see PRO-3192).
* [BREAKING] The inverted twin of that guard: an `exclusion:` set — or a `comparison: { other_than: ... }` bound — no value of the declared `type:` could ever be is refused at declaration, at **every** type. Inverted validators read their literals to decide when a check FAILS, so wrong-type literals make the check impossible to fail rather than impossible to pass: `type: Array, exclusion: { in: ["admin"] }` accepted `["admin"]`, `type: Integer, exclusion: { in: ["1", "2"] }` accepted every Integer, and `type: Integer, comparison: { other_than: "a" }` accepted every Integer — the author wrote a constraint, the class defined cleanly, and every value passed. Judged by the same readers, the same closed equality world and the same stand-downs as the satisfiability guard, on the opposite verdict: a forbidden set is vacuous exactly when its `inclusion:` mirror would be unsatisfiable, an empty one included. It stands down on everything that guard does — a set axn may not read side-effect-free, a dynamically-sourced one, an undeclared or pseudo-type `type:`, a `Range` at a scalar position, a Symbol/Proc bound, any class pair outside the closed world — and additionally on a declared SUPERTYPE, since `type: Object, exclusion: { in: ["admin"] }` really does forbid the `String` that type admits. `comparison:` is judged only where the bound is the sole thing the entry can reject: ActiveModel rejects a **blank** value ahead of any bound, so an entry on a type that has one (`Array`, `Hash`, `Set`, `String`, `Symbol`) enforces something whatever the bound says — `type: Array, comparison: { other_than: 1 }` really does reject `[]` — and stands down, leaving the rule to a type with no blank value or to an entry whose `allow_blank:` puts them out of reach. Two rules differ from its mirror, both following from the inversion: tolerance never rescues one (a tolerated nil is one more value that passes, and no amount of passing makes a check something can fail) but instead **discounts forbidden literals**, since ActiveModel skips a tolerated value before any validator sees it — so `type: NilClass, exclusion: { in: [nil] }, allow_nil: true` and `type: Array, exclusion: { in: [[]] }, allow_blank: true` are refused for forbidding only what the flag exempts, while a literal the flag does not skip still counts; and a gate does not excuse one because a gate can only remove the check — closed it enforces nothing, open it enforces nothing. Vacuity is judged for those two validators only: `length: { maximum: Float::INFINITY }` and `length: { minimum: 0 }` enforce nothing but are ActiveModel's own spelling for "no bound", a `format:` pattern matching every string is not detectable in general (a shortlist of broken patterns is an exception list that cannot be completed), and vacuity for a non-inverted set would need the declared type's whole value space to sit inside it — knowable only for `nil`/`true`/`false`. All four still declare (see PRO-3218).
* [BREAKING] A top-level `expects` now runs the **full** set of subfield contradiction checks, where it ran only the map-parent one. A top-level declaration carries no `on:`, so it looks like it can contradict no subfield — but an explicit top-level field OUTRANKS a same-named subfield's reader, so declaring one takes that reader over and **re-anchors** every subfield anchored on the name onto the new root. `expects :counts, on: :payload` then `expects :n, on: :counts` then `expects :counts, type: String` declared cleanly and was unsatisfiable for every input — `counts: "hi"` failed `N can't be blank`, `counts: {n: 5}` failed `Counts is not a String` — while the emitted schema advertised `counts` as a plain string and dropped `:n` from the document entirely, the worst failure shape available: no error, and a schema omitting what was declared. Two families newly raise at declaration, both only ever reached through a re-anchor: a parent whose declared type can never answer the subfield's segment (`type: String`, `Integer`, `Array`), and a nil-tolerant parent (`allow_nil:`/`optional:`/`allow_blank:`) whose newly-adopted required child nothing rescues. Re-anchoring onto a map (`of:`) already raised. This also closes the ambient variant, where the takeover pulls a subfield out of the ambient subtree onto a scalar root. What stays legal is unchanged: a re-anchor onto a `Hash`, onto a `model:` route (a record's method surface is never statically refutable), or onto a type whose method surface does answer the segment; and any top-level field that takes over no reader at all — a dotted wire segment merely sharing the name is a different node (`expects :baz, on: "payload.bar"` reads `bar` out of `payload`, so a later top-level `:bar` strands nothing). The checks are skipped outright on a contract that declares no subfield, so a subfield-free contract sees none of this (see PRO-3169).

### Fixed

* [BUGFIX] `CallLogger.format_object` no longer costs — and renders — exponentially in a logged value's nesting depth. Its `Array` branch handed the parent a raw `Array` of already-formatted `String` children instead of a `String`, unlike the sibling `Hash` branch beside it; interpolating that `Array` via `#{}` ran `Array#to_s` (`== #inspect`) over the already-rendered children, re-escaping their quotes and backslashes — and that re-escaping compounded once per nesting level. This sits on the automatic before-execute log line, so it cost every call in every process that logs, with **no `shape:`/`of:` contract required to trigger it**: `expects :m, type: Array` alone, called with a value nested 29 levels deep, took ~23s to log and produced a line no one could read; it now logs in single-digit milliseconds. The `Array` branch now composes into a `String` directly, mirroring the `Hash` branch, so a rendered child is never re-inspected by its parent (see PRO-3203). A leaf value (and an `ActiveRecord::Base` record's `<Class#id>` rendering) is now rendered through `Internal::Text.renderable` rather than its raw `#inspect`/`to_param`, closing a related (pre-existing, not introduced by the above) hole in the sibling `Hash` branch too: a caller object whose own `#inspect` — or a record's `to_param` — hands back non-ASCII bytes in a foreign encoding, unescaped, previously blew up the composing `.join` with `Encoding::CompatibilityError` — and lost the log line entirely, swallowed by the surrounding `best_effort` — the moment a SECOND such value anywhere in the same structure disagreed on encoding.
* [BUGFIX] A declared `length:` ceiling now reflects into the schema as `maxItems` / `maxProperties` / `maxLength`, at every position — only the floor was ever emitted, so `length: { maximum: 2 }` advertised no bound at all while the runtime enforced one. An exact `length: { is: 2 }` emits both bounds, a range emits both (an exclusive end counting one less, as ActiveModel resolves it), and a union emits each bound on every size-bearing `anyOf` branch. A bound ActiveModel resolves per call (a Symbol/Proc) and `Float::INFINITY` emit nothing, since no fixed number expresses them (see PRO-3192).
* [BUGFIX] A declared type whose own `to_s` raises no longer replaces an inbound validation failure with its exception. `type:`, an Array's `of:`, and a map's `keys:`/`values:` all interpolated the declared class into the mismatch message, so a class raising there settled a plain contract violation as an **exception** outcome reading "Something went wrong" — and reported bad input through `Axn.config.on_exception` as though it were an internal error. All three now name the type through one shared seam that reads a class's name natively; the wording is unchanged for every ordinary class and pseudo-type (see PRO-3165).
* [BUGFIX] An inherited `ambient_context` is no longer shadowed with no warning at all, the one deferrable name PRO-3149 left out. It now defers exactly like axn's other seventeen sugar names — announced once, and confirmable with `prefer_inherited`/`prefer_axn` — because handing over the *method* costs nothing (internals bind that reader rather than dispatch it). A field declaration of that name is unaffected and still raises: that is a different, sentinel-comparison reason, unrelated to whether an inherited method may be deferred to (see PRO-3173).
* [BUGFIX] `mount_axn`/`mount_axn_method`/`step` onto an `ActiveRecord::Base` model now construct correctly. `ActiveRecord::Base` defines its own class-level `.new(attributes = nil)`, which the mounted action's superclass chain inherited and forwarded a positional argument through into axn's kwargs-only `#initialize(**)`, raising `ArgumentError: wrong number of arguments` on every mounted call — a pre-existing limitation, not a PRO-3149 regression, that PRO-3149's own construction guard merely made visible. Every class `Axn::Factory.build` constructs now defines its own `.new` directly on its singleton table, which always outranks whatever a `superclass:` ancestor's own `.new` does, so this also fixes the identical crash for any `Axn::Factory.build(superclass: ...)` caller whose superclass overrides `.new` (see PRO-3173).

* [BREAKING] An `of:` bag now only accepts the keys its container allows: `klass:`/`message:` plus the shared ActiveModel options (`if:`, `unless:`, `allow_blank:`, `allow_nil:`, `strict:`) for an Array; `keys:`/`values:` plus those same shared options for a Hash. (`on:` is admitted by this same whitelist but never works: it is unconditionally refused by the pre-existing "axn has no validation contexts" check, for an `of:` bag exactly as for any other validator's options.) Anything else now raises `ArgumentError` at declaration — a misspelled option (`mesage:` for `message:`), or any validator the bag does not own — where it declared cleanly against 0.1.0-alpha.5.1 and silently constrained nothing. Drop the unsupported key, or fix the misspelling; the error names every offending key at once (see PRO-3165). A nested `of:` (`of: { klass: Array, of: Integer }`) and a nested `shape:` were refused by this same whitelist; both are admitted below by PRO-3166, which widens the bag to `klass:`/`of:`/`shape:`/`message:`.
* [BREAKING] A wrong-typed element under `type: Array, of: Hash` with a shape block now reports the type error **alone**, where it also reported a member line before. `expects :items, type: Array, of: Hash do field :sku, type: String end` called with `items: ["nope"]` settles as `element at index 0 is not a Hash`; it previously settled as `element at index 0 is not a Hash and element at index 0: sku could not be read (got String)`. A container's contents now live in its `of:` bag with the element's own class as their gate, so a String element never reaches member validation at all. This **converges** the flat spelling on what `of: { klass: Hash, shape: ... }` has always reported — the two spellings now agree, which is the point of the change — but an assertion matching the old two-clause string has to be updated. Only the case where the element class can gate the members changes: `of: Array` and `of: String` with a block still pair an element type error with the member line, since neither can be read as "read the members off this element" (see PRO-3166).
* [BREAKING] A **distributing** `shape:` chain — `type: Array` with a block, whose member is itself `type: Array` with a block, repeated — now nests at most **32** levels deep; the 33rd raises `ArgumentError` when the class is defined (`a shape: graph nested more than 64 levels deep at shape member ...`). **A 33-to-65-level contract previously declared *and* validated correctly, end to end — measured at 0.1.0-alpha.5.1 and at the branch base — so this narrows a contract that used to run, loudly at declaration rather than quietly at runtime.** Each authored level of that spelling now folds into an `of:` bag carrying the element's shape, which costs two rungs of the single 64-rung nesting budget where it used to cost one. Nothing else moves: a `type: Hash` block chain still nests 65 levels, and so does a hand-written bag chain (`of: { klass: Array, of: { ... } }`) — one rung per level against the same 64-rung budget, so 65 links declare and the 66th raises. A contract that deep almost certainly wants restructuring anyway; if you genuinely need the depth, spell the tail as a bag chain (`of: { klass: Array, of: ... }`), which charges one rung per level (see PRO-3166).
* [BREAKING] `shape:` no longer distributes over an Array's elements when supplied as a raw kwarg. `shape:` has always meant "the members of this value"; on `type: Array` it instead meant "the members of each element", an exception that existed only because `of:` had no way to name an element's own members. PRO-3166 gave `of:` that word recursively, so the exception is retired: `expects :rows, type: Array, of: Hash, shape: { members: [...] }` now raises `ArgumentError` at declaration, naming the nested spelling it used to canonicalize into — `of: { klass: Hash, shape: { members: [...] } }` (or `of: { shape: { members: [...] } }` to leave the element class open). The **block** form is unaffected and is the documented spelling: `type: Array, of: Hash do field :sku, type: String end` still declares and still distributes, since a block is the one route with no other honest reading of `type: Array`. A raw shape hand-writing `container: Array` on any OTHER type is refused the same way, wherever it is written (a field's own shape, or a member's, at any depth) — that spelling was a live divergence against 0.1.0-alpha.5.1 rather than a working feature losing support: `ShapeValidator` reads `container: Array` as "distribute", so it never reached member validation for a non-Array container, and a declaration like `expects :row, type: Hash, shape: { container: Array, members: [...] }` published its member's type in the schema (`required: [...]`) while enforcing none of it. Rewrite a raw flat spelling to the `of:` bag it canonicalized into, or to the block form (see PRO-3191).
* [BREAKING] `of: []` and `of: { klass: [] }` now raise `ArgumentError` when the class is defined. An empty class union names no class, so nothing at that position was ever held to anything — while the reflected schema emitted `items: { anyOf: [] }`, which no element satisfies, leaving the published document and the enforced contract disagreeing in the loosening direction. Nobody can be running this: before the recursion below, an Array's element path rejected **every** element against an empty union, so the declaration failed 100% of calls; the recursion rewrote that path onto the shared axis matcher, whose "an omitted axis is unconstrained" early-true is right for an axis and wrong for an element. Emptiness is now asked one way everywhere (`Array(klass).empty?`), so the same refusal covers `of: { values: { klass: [] } }` and `of: { keys: { klass: [] } }` — the bare axis spelling `of: { values: [] }` was already refused on exactly these grounds. Name the class(es) the contents must be, or constrain them with `of:`/`shape:` instead (see PRO-3166).
* [BREAKING] A **class token the runtime cannot hold a value to** now raises `ArgumentError` when the class is defined, wherever an `of:` bag names one. `of: false`, `of: { klass: 5 }`, `of: { klass: [String, nil] }` and every nested spelling of them (`of: { values: { klass: false } }`, `of: { keys: { klass: 5 } }`, `of: { klass: Array, of: { klass: false } }`, the same bag inside a shape member's own `of:`) declared cleanly against 0.1.0-alpha.5.1 and then raised a bare `TypeError: class or module required` out of `value.is_a?(false)` on the first call carrying a non-empty container — an exception outcome reading "Something went wrong", naming neither the field nor the option, and reported through `Axn.config.on_exception` as an internal error. Nobody can be running one: every call carrying contents failed. A bag's `klass:` is now held to exactly the grammar a map's bare axis is, by the same predicate — a Class or module, a union of them, or one of `:boolean`/`:uuid`/`:params` — and the refusal names `klass:` rather than the axis it was written under, since `klass:` is what there is to fix at every one of those positions. A union is judged member by member and the offending member is what gets named. Two spellings are deliberately left to the guards that already own them: an empty or absent `klass:` (`of: { klass: [] }`) still gets the constrains-nothing message above, and a bag naming its own `of:` still gets `of: requires klass: Array or Hash`, which is the narrower fix. The same fix closes it for a **bare axis** too, where a `nil` inside a union (`of: { values: [String, nil] }`) slipped past the axis check that had refused `values: nil` since PRO-3165 (see PRO-3166).
* [BREAKING] A **class token the runtime cannot hold a value to** now raises `ArgumentError` when the class is defined, wherever a field's own `type:` names one — the last position of the defect above, closed everywhere else in an `of:` bag. `type: false`, `type: 5`, `type: "String"`, `type: [String, nil]` and `type: { klass: false }` declared cleanly against 0.1.0-alpha.5.1 and then raised the same bare `TypeError: class or module required` out of `value.is_a?(false)` on the first call, at every position a field's `type:` reaches: `expects`, `exposes`, a subfield, an ambient subfield, and a shape member (block or raw). Nobody can be running one: every call failed. Held to exactly the grammar `of:` already is, by the same shared predicate — a Class or module, a union of them, or one of `:boolean`/`:uuid`/`:params` — with the refusal naming `type:`. Unlike a bag's `klass:`, a field's `type:` has no second option left to constrain it, so "supplied but names nothing" is refused here rather than deferred: `type: nil`, `type: []` and `type: { klass: [] }` raise too, on the same terms the bare `of:` axis already does. Deferred when `of:` is also declared, since it already holds `type:` to a narrower rule (Array or Hash only) and names the fix that actually applies — `of: false, of: Integer` still gets `of: requires type: Array or Hash`, not this message. Deliberately **not** deferred to a `shape:`, even though its own container derivation often independently judges `type:` too: that path is conditional on the shape supplying no `container:` of its own, and telling the two states apart would mean re-reading the shape's `container:` a second time, independent of whatever the derivation code reads — a `[]` that answers differently between the two reads (never an ordinary Hash) could then let a bad `type:` through both checks. Checking `type:` here unconditionally whenever `shape:` is present removes the need to predict the other path's behavior at all, at the cost of one changed message: a bad `type:` beside a `shape:` now reports this guard's `type:`-specific wording rather than the shape's derived "container: must be a class" one. `_declared_type_tokens` — the union-or-single-token classifier this guard shares with the `of:` bag's `klass:` guard — now reads that split through `case`/`when ::Array` rather than `Kernel#Array()`, which tried a declared value's own `to_ary` (then `to_a`) before wrapping it: an object defining `to_ary` decided how it was read (returning `[String]` waved a genuinely unsupported token through as a "union" naming a real class), and one whose `to_ary` raised replaced the declaration error with whatever it threw. Fixed at the one shared function both callers go through, and reused at `_declared_of_container!` (the container `of:` derives from a field's own `type:`), which had its own separate, unrelated `Array()` call reachable through `type:`'s deferral to `of:` — closing that route too (see PRO-3207).
* [BREAKING] The same fix closes the identical hole in `model:`'s `klass:`, now raising `ArgumentError` at declaration for a token `ModelValidator` cannot resolve a record through: `model: 5`, `model: :nonsense` and `model: { klass: 5 }` declared cleanly against 0.1.0-alpha.5.1 and raised the same bare `TypeError` on every call, since `ModelValidator#validate_each` delegates straight into `TypeValidator`. The grammar is narrower than `type:`'s, though: a model field resolves a record by calling a finder method **on** `klass:`, never by asking a value `is_a?` of it, so `klass:` must now be a single Class or Module — a union or a `:boolean`/`:uuid`/`:params` pseudo-type is refused rather than accepted, closing a second, quieter hole along with it: `TypeValidator` iterates a union happily, so `model: [A, B]` previously passed the type check only for `FieldResolvers::Model#derive_value` to call `Array#find` (via `Enumerable`) instead of either class's own finder, silently resolving to the wrong thing under `best_effort` rather than raising at all. No spec, doc, or downstream consumer ever declared `model:` with a union or a pseudo-type. Also closes the case where `klass:` is explicitly `false`/`nil`: `ModelValidator.apply_syntactic_sugar`'s `options[:klass] ||= fields.first.to_s.classify` fallback previously treated every falsy `klass:` as a "please infer" request, same as `model: true` — so `model: false` either raised a confusing `NameError: uninitialized constant User` (no such constant) or silently, successfully resolved through `User` (one happens to exist), depending on unrelated global state. Neither spelling was ever documented, so `false`/`nil` now raise `ArgumentError` outright, before the inference fallback ever runs — `model: true` (the documented "please infer" spelling) and an absent `klass:` (`model: { finder: :find_by_slug }`, which only overrides the finder) are unaffected (see PRO-3207).
* [BUGFIX] A cycle running through an **`Array`-typed shape member** is now masked in the automatic log line instead of being rendered until Ruby's own cycle marker stops it. `expects :items, type: Array do field :children, type: Array do field :ssn, type: String, sensitive: true end end`, called with `items = []; items << { children: items }`, logged `{items: ["{children: [\"{children: [\\\"{children: [...]}\\\"]}\"]}"]}` and now logs `{items: ["{children: \"[FILTERED]\"}"]}`. An `Array`-typed member's contents are now declared in its `of:` bag, so redaction's own container walk descends that edge and its guard sees the array reappear beneath itself, masking wholesale — the over-redact-rather-than-leak call every revisit on that walk makes. Previously the innermost rung returned `element.dup` ahead of its own guard, which handed the caller's cyclic Array back to the logger and left `inspect` to render it. Over-redaction, so the safe direction, but a log line that used to show the repeated structure now shows `[FILTERED]` for it. A `Hash`-typed member is unchanged (`{items: {children: {children: {children: {...}}}}}` before and after), as is a flat unshaped cycle, which still renders `[...]` (see PRO-3166).
* [BUGFIX] An instance method your own class hierarchy already declares is no longer silently shadowed by axn's helper of the same name. `include Axn` puts its convenience helpers in a module, and Ruby ranks a module included into your class *above* that class's superclass — so an `ApplicationService#log` was there in the source and unreachable from the action, with nothing said about it. Axn now steps aside for any of its 17 helper names (`fail!`, `done!`, `forward!`, `result`, `inputs`, `expose`, `default_error`, `default_success`, `execution_context`, `set_execution_context`, `clear_execution_context`, `log`, `debug`, `info`, `warn`, `error`, `fatal`) that your hierarchy declares — a superclass, or a module you included before `include Axn` — calling the inherited implementation at its original visibility, and logs **one warning per inherited method** the first time such an action runs (not at load: an action nobody calls announces nothing). Names Ruby owns are unaffected, because the walk stops at `::Object`: `warn("msg")` inside an action still reaches axn's logger rather than stderr. A `def` in the action's own class body is unchanged too — it wins, with `super` reaching the inherited implementation where you have one and axn's where you don't. Two new class-level declarations say which implementation is live: `prefer_inherited :log` confirms the deferral and silences the warning for that name, and `prefer_axn :fail!` puts axn's implementation back in front (the only route to it, since `super` from your own `def` reaches the inherited version). Each is scoped to the class that writes it, so a subclass may choose differently without changing its parent's or its siblings' behavior. Documented at [Inheritance & Method Conflicts](https://teamshares.github.io/axn/advanced/inheritance) (see PRO-3149).
* [BREAKING] An inherited `call`, `_run` or `initialize` now raises `Axn::ContractViolation::UnsurrenderableInheritedMethod` at the action's first `.call`, where it previously reported **success** for code that never ran. Axn dispatches those three names on the action itself to run it, so a superclass's version can never execute — `class ChargeCard < ServiceBase; include Axn; end` returned `ok? == true` without `ServiceBase#call` ever being reached, and an inherited `initialize` left the parent's state unset just as quietly. Either move that behavior into the action's own `call`/`initialize` (note that a bare `super` from there reaches axn's default, **not** the parent's), or compose the parent in rather than inheriting from it, which is the branch that keeps its implementation running. A class that defines the name itself is never refused, so this also reaches `Axn::Factory.build(..., superclass:)` asymmetrically: the factory defines `call` on the class it builds, so a superclass owning `call` still works, but one owning `initialize` now raises where it previously ran with the parent's initializer skipped. Actions axn builds for **mounting** are exempt: `mount_axn`, `mount_axn_method` and `step` pick the superclass themselves (that is what `inherit:` selects, so the mounted action carries the target's hooks, callbacks and async config), so mounting onto a target that defines `initialize` keeps working — neither remedy above could be applied to a class you did not write. A mount that passes its own `superclass:` is refused like any other (see PRO-3149).

Separately, that same declaration path asked the class for its own instance methods to detect a pre-existing `#call`; a class under-reporting them was admitted, and the generated step orchestrator silently replaced the `#call` its author wrote. Both reads now come out of the class's OWN method table — not effective lookup, which a prepended `#call` changes: a class defining `#call` that also prepends a module defining one resolves the name to the prepend, so an owner comparison would call the author's definition absent and overwrite it. Previously it received whatever a declared `error` handler returned or a caller passed `fail!`, so interpolating it inside the Proc dispatched that object's `to_s` (see PRO-3035).
* [BUGFIX] A `user_facing:` handler returning a String whose class also defines `to_ary` now surfaces its text instead of being dropped in favour of the field's own validation message.
* [BUGFIX] `expose(result)` no longer writes `nil` over a value the absorbing action had already exposed under the same name. The merge keyed on the source's *declared* exposures, so a field the source declared but never set forwarded as `nil` and erased the existing value (see PRO-2941).
* [BUGFIX] A field declared as both `expects` and `exposes` is no longer written onto the result when the caller supplied nothing for it and it resolves to `nil`. The outbound auto-copy wrote the key unconditionally, which was invisible through the field's own reader (an absent key reads `nil` too) but made the result claim it carried a value it did not — so absorbing that result via `expose(result)` or `forward!` overwrote the absorbing action's own value for that name with the synthesized `nil`. The copy keys on presence rather than value, so a caller who explicitly passes `field: nil` still gets that nil on the result and still forwards it. Reading the field is unchanged; a result pattern-match on a field the caller never supplied no longer binds it (see PRO-2941).
* [BUGFIX] `expose(result)` no longer raises `NoMatchingExposures` when the source result failed and shares no exposures with this action. The raise replaced the source's own error message with a contract violation and downgraded a clean failure to an exception. It still raises when the source succeeded, where an empty intersection is a wiring mistake and nothing is lost by saying so (see PRO-2941).
* [BUGFIX] `confirmation:` now enforces a confirmation. It was accepted at declaration and could never fire in any spelling: ActiveModel's `ConfirmationValidator` defines a real `<field>_confirmation` accessor on the one-off validator class axn builds, nothing ever populated it, and because the accessor is real it also shadowed the fallback that would have let a hand-declared companion field supply the value. `expects :password, confirmation: true` now declares a `password_confirmation` input implicitly — inheriting the base field's `type:`, `coerce:`, `preprocess:`, `method_call:`, `user_facing:` and `sensitive:`, never its `default:` — and requires it exactly when the base field is present and the comparison runs (an `if:`/`unless:` on the declaration or on the `confirmation:` entry itself gates the companion's requirement too, so a disabled confirmation never rejects an omitted companion). Note the deliberate difference from ActiveModel, whose default accepts an omitted confirmation (see PRO-3023).
* [BUGFIX] A conditionally-required typed field now reports a nil in one clause, as an unconditionally-required one already did — `expects :name, type: String, if: :flag` omitted under a true `flag` now raises `"Name is not a String"` rather than `"Name is not a String and Name can't be blank"`. The declaration-time nil-skip push-down (which relaxes every other validator on a field whose type check already rejects nil, so only one of them reports it) stood down whenever the type entry carried an *effective* if:/unless: gate — declaration-level gates included, even though a declaration-level gate opens and closes every validator on the field together and so never lets one validator run where the type check doesn't. It now stands down only where a gate can actually desynchronize a validator from the type check: a non-blank gate the type entry carries itself, or — where the type check rides a declaration-level gate — a sibling that overrides one of those gate keys BY NAME (ActiveModel merges the two tiers per key, so a sibling naming some other key keeps every shared condition and merely adds one, and a blank value gates nothing at all). An unconditional type check runs on every call any sibling does, so neither a sibling's own gate nor a blank gate key on the type entry costs a second clause (see PRO-3023).
* [BREAKING] `confirmation: true` is rejected at declaration on `exposes` and inside a shape block's `field`. Previously it was accepted silently and could never fire (see above); now that it declares and enforces a real companion, neither route can support one — `exposes` has no caller input to confirm an output against, and a shape member has no reader for a companion to attach to — so both raise `ArgumentError` at class-definition time instead of loading cleanly (see PRO-3023).
* [BREAKING] `Axn::Extensions.config.register_field_metadata_key` now raises `ArgumentError` for a name the core field DSL already owns, where it previously accepted any symbol. `_partition_field_options` routes a declaration's keys by that registry, so a gem claiming a core option name moved the key out of the validations bag and silently changed what it meant — `register_field_metadata_key(:type)` turned `expects :x, type: String` into an unchecked field carrying `{ type: String }` as metadata, and broke every `type:`-bearing shape block in the process, since `_build_shape` derives its container from that same key. All 33 owned names are refused: the validation keys, ActiveModel's shared options, and the `expects`/`exposes`/shape-member field options — including the ones Ruby binds as kwargs before `**` collects them, which could not be misrouted but registered a metadata key no declaration would ever route to. The set is derived from those declarations rather than listed beside them, so an option added to `expects` later is reserved with it. No axn gem registered a colliding name, so nothing downstream changes; a gem that did should namespace the key (`:mcp_title`). Registration is all-or-nothing — a call naming one reserved key registers none of its keys (see PRO-3067).
* [BREAKING] A dotted `on:` path may no longer read through a wire node that two routes declared. `expects :baz, on: "foo.bar", as: :b1` beside `expects :baz, on: :bar, as: :b2` is one merged wire node with two readers, and a third declaration reading down through it — `expects :src, on: "foo.bar.baz"` — named the node rather than either route, so the first-declared route's `preprocess:`/`default:`/`model:` supplied the value to everything below it. Swapping those two lines silently changed what `src` resolved to, with nothing raised and the emitted schema identical either way. Such a reference now raises at declaration naming both routes. Anchor on the route you mean (`on: :b1` or `on: :b2`), declare the wire key once, or split the routes onto distinct wire keys. A dotted tail over an *undeclared* intermediate is untouched (that is what implicit intermediates are for), as is a tail over a single-route declared node, and so is a node whose routes share one reader name — an inferred `confirmation:` companion beside your own same-named declaration dispatches through the reader-owner rule, which declaration order cannot change (see PRO-3068).
* [BREAKING] A `model:` field's `<field>_id` lookup token now comes only from the id route declared beside it (same `on:`) or the route that owns the canonical `<field>_id` reader name. Previously any route declaring that wire key could supply it, chosen by declaration order among defaulted routes — so `expects :company_id, on: "payload.thing", as: :other_id, default: 7` supplied the token for `expects :company, on: :thing, model: Company` even though nothing pointed it at that model and its reader was named something else. A `default:` resolves on the read path and is never written to the wire, so it is a fact about its own reader; an `as:`-renamed route on another spelling now supplies nothing and the caller's raw token is used instead. Both selectors are single-valued by construction (reader names are unique; a second config on the same route with the same wire key is already a duplicate-field error), so no ambiguity is left to resolve by order. The model-consistency check moves with it: a directly-supplied record is now compared against the raw token rather than an ineligible route's transform, so only a transform that actually changes the string form (`_record_id_mismatch` compares via `to_s`) — a normalizing `preprocess:`, a coerce to a different id type — can still turn a conflict into a match or a match into a conflict. If you relied on the old rescue, declare the default on the model's own route or drop its `as:`. A nil-tolerant `model:` that stood only because such a route was credited with rescuing it now raises the existing dead-tolerance error at declaration rather than resolving nil at run time (see PRO-3068).
* [BUGFIX] Two `default:` declarations on one merged wire node are legal again. The rejection added for PRO-2901 was justified by an inbound write-back — the first-declared default writing the shared wire key — which PRO-2903/2908 removed; each route now resolves its own default on its own read path, and the one consumer that still picked among them by order is fixed above. One route raw with a String default beside one coerced with an Integer default is a coherent contract. This does widen an existing, out-of-scope divergence: the emitted schema's own `default` at a merged node still comes from the first non-model route (`property_representative`), so which literal the schema advertises — as opposed to which literal each reader resolves — stays declaration-order-dependent; the same contract emits `{"count":{"type":["integer","null"],"default":42}}` with the routes declared one way and `{"count":{"default":""}}` with them swapped (see PRO-3068).
* [BUGFIX] An outcome auto-logged at `:error` (e.g. `Axn.config.log_level = :error`, or `auto_log :error`/`auto_log exception: :error`) now actually reaches the configured logger, instead of raising and being silently swallowed. The automatic-logging hook dispatched by calling a same-named class method (`action_class.public_send(level, ...)`), meaning to reach `Core::Logging`'s per-level convenience method — but `Core::Flow::Messages` also defines an `error` class method (the `error "..."` DSL for declaring a custom error message), and it wins method resolution over the logger's `error`. So every `:error`-level auto-log call actually invoked the DSL method, which rejected the incoming `before:`/`after:`/`prefix:` as unknown options; `Axn::Extensions.best_effort` then swallowed the resulting `ArgumentError`, replacing what should have been a log line with an internal "IGNORING EXCEPTION" warning, even though the call itself settled normally. `debug:`/`info:`/`warn:`/`fatal:` were unaffected — `Messages` claims only `error` (and `success`, which is not a log level). The hook now calls the logger's own `log` method directly rather than dispatching by level name, avoiding the ambiguity entirely (see PRO-3042).
* [BUGFIX] Shadowing an axn instance method no longer corrupts the framework. `include Axn` puts its helpers on your class, and axn's own internals used to dispatch back through those same names — so a user's own `def` or field declaration didn't just cost you the helper, it broke the framework in ways that were invisible until you went looking. Previously: `def result`, `expects :result`, and `expects :log` ran the action but silently swallowed one or more internal `NoMethodError`s along the way; `expects :internal_context` broke every *other* field's reader, because the generated reader's own body dispatched `internal_context` by name; `expects :call` was the worst of the four — the action reported `ok? == true`, `outcome == :success`, for a body that **never ran**; and a parent action with `def fail!` swallowed a failing step's exception and reported success instead. Internals now read action state through `Axn::Internal::ActionState`, which holds each real implementation as an `UnboundMethod` and `bind_call`s it directly, rather than dispatching a name the receiver could intercept — so taking one of these names now costs exactly the helper, and nothing else (see PRO-3062).
* [BREAKING] Declaration-time name checks for `expects` are now derived from method ownership instead of two hand-maintained reserved-name lists. Newly **rejected**: `expects :call` / `:_run` (the two names the framework itself dispatches to run the action — taking either previously produced the silent-success bug above, now a `ReservedAttributeError` at declaration), any name owned by Ruby or ActiveSupport (`expects :class` previously recursed through the framework's own internals until `SystemStackError`; it now raises the same reserved-name error as any other collision), and any name an earlier `def` in the class body already owns. Newly **allowed**: axn's own user-facing sugar, which used to be refused for no reason tied to an actual collision — `expects :result`, `:log`, `:error`, `:info`, `:warn`, `:debug`, `:fatal`, `:inputs`, `:expose`, `:execution_context` all declare cleanly now. `ambient_context` stays reserved, and is not sugar: it is the sentinel the subfield resolver compares a route's root against, so a field of that name would be answered by the ambient branch and hand back the ambient context instead of the declared value. A declaration lands two names on two receivers, and each is judged where it lands: the generated **reader** on the action class, and the **wire key** on the inbound context facade, which builds a reader per declared field and will not define one over its own methods. So `as:` (or `prefix:`) is the escape hatch for a reader collision — `expects :format, as: :fmt` keeps `format` as the caller-facing key and renames only the reader — while a wire key the facade owns (`default_error`, `default_success`, `declared_fields`, `action`, `action_name`, `context`, `inspect`, `fail!`) is refused however the reader is spelled, because those options leave the key as written. One shape has no route to the reader escape either: the factory / `mount_axn` block-parameter form declares one field per block keyword parameter, with no separate `as:` slot to rename the reader — `format:` as a block parameter still collides, and adding `as:` there fails its own way ("Reader name collision"). A reserved name reached that way has to be renamed at the parameter itself (see PRO-3062).
* [BREAKING] Declaration-time name checks for `exposes` are likewise derived from ownership — judged against `Axn::Result`'s own public API, plus the non-method surface its contract carries: the keys `deconstruct_keys` itself emits (`ok`, `finalized`, alongside the already-owned `success`/`error`/`message`/`outcome`) and the control kwargs `fail!`/`done!` read ahead of an exposure of the same name (`standalone`). An exposed field is readable inside the action body too — the inbound context facade carries it as an implicitly-allowed field — so a name that facade owns (`default_error`, `default_success`) is refused on those grounds rather than by `Result`. **159 names are newly refused.** Previously `exposes :hash` made two Results with the same exposed value collide as one entry in a `Set`; `exposes :class` made `result.class` return the exposure instead of reporting the Result's own type; `exposes :deconstruct_keys` declared cleanly and then broke `case result in { … }` with a confusing `ArgumentError: wrong number of arguments` at the call site instead of a message at declaration. Only four names were freed, having been reserved even though nothing on `Result` (or its contract) answers to them: `ambient_context`, `each_pair`, `inputs`, `result`. **`exposes` has no `as:`, so there is no escape hatch for a newly-refused name — the field itself has to be renamed.** The refused set is also environment-dependent: it is derived from whatever has patched `Object` in the process that loads axn, so a gem present in a host app but absent from axn's own test suite can turn a previously-legal `exposes` into a declaration-time raise purely from the upgrade, with nothing in axn's own diff to blame (see PRO-3062).
* [BREAKING] `internal_context` is no longer a public instance method. It was framework plumbing that only the internal funnel above needs; `action.internal_context` now raises `NoMethodError`, and the name is free for a field or method of your own (see PRO-3062).

* [BUGFIX] The Rails engine now registers even when `axn` is required before Rails. `require "axn"` loaded `axn/rails/engine` only if `Rails` was already defined, and re-requiring axn later is a no-op — so a host whose `spec_helper.rb` requires `axn/testing/spec_helpers` (the placement we document) ahead of the `rails_helper.rb` that boots the app got no engine at all. Without it `app/actions` never received its configured `app_actions_autoload_namespace`, Rails pushed the directory at the root namespace instead, and every constant under it was unresolvable — in the test environment only, so a passing boot said nothing. Introduced in 0.1.0-alpha.5, when `axn/testing/spec_helpers` began requiring `axn/testing` (and through it the full gem). The engine load is now deferred to `ActiveSupport.on_load(:before_configuration)` when Rails is absent at require time.

### Performance

* [INTERNAL] The one-off ActiveModel validator class for a declared field/subfield is now compiled once per class and reused across every `.call`, instead of being recompiled (and its ActiveModel validator machinery re-instantiated) on every call. `auto_log` no longer builds its before/after payload when the configured logger's own severity level would discard it. `_model_fields` and `_declared_fields` are now cached per class instead of being rebuilt from the full contract on every reader definition / every read. Recovers roughly half of alpha-5's per-call allocation increase on the `basic` benchmark scenario — 489 → 250 objects/call (see PRO-3050).
* [BREAKING] `Result#declared_fields` now returns a frozen Array. Previously each call built a fresh Array, so appending to the one handed to a given result had no effect beyond that call; the Array is now cached and shared across every call of the class (see above), so mutating it raises `FrozenError` instead of silently being a no-op.

## 0.1.0-alpha.5

Most of what follows announces itself: a new option, a rename, or a declaration error you now get at class definition instead of on every call. These are the changes that do **not** — re-run your suite and look at these areas.

* `on_success` fires after the enclosing transaction commits, and is skipped on rollback.
* A step that raises an unexpected exception settles its parent as an exception rather than a failure, so `on_failure` no longer fires for it.
* The Sidekiq adapter no longer makes actions `Sidekiq::Job`s, and the wire format changed — drain the queue across the deploy.
* Subfield `coerce:`/`preprocess:`/`default:` resolve on the read path, and the parent is never materialized or mutated to apply them.
* A `model:` field's record and key reads route through the canonical reader path, and passing a record together with a contradictory `<field>_id` now fails the call instead of silently preferring the record.
* A nested `call!` re-raises the inner action's own exception instead of wrapping it in `Axn::Failure`.
* Exception reports carry the declared, filtered `ambient_context` in place of the `current_attributes` key.
* `SystemStackError` and `ScriptError` settle as exception outcomes instead of escaping `.call` unreported.
* An empty container is now a failure reason: `fail!([])`, or an `error`/`success` handler returning `{}`, renders that object rather than falling back to the default message.
* `Axn::Extensions::Serialization.render` rejects values it used to emit (a cycle, a non-finite Float, two Hash keys that render as one property), which an adapter sees as a failed render rather than a wrong body.
* On an `Axn::Configurable` setting, a Proc `default:` is now invoked on every unset read, while an assigned Proc is returned as-is rather than called.

One audit rather than a re-test: `sensitive:` and `user_facing:` now reject values they used to accept and silently ignore, so a declaration that starts raising at load is telling you it never did anything — `sensitive: 1` was logging that field in the clear.

### Field contract & subfields

* [BREAKING] Field keys are normalized to symbols, giving the contract indifferent access: `expects "note"` ≡ `expects :note`, `.call("note" => …)` ≡ `.call(note: …)`, and splatting a string-keyed params hash into `.call(**params)` no longer silently reads `nil`. Top-level keys only — field values, including nested hashes, are untouched. A subfield's `on:` route, an `as:`/`prefix:` rename, and `Axn::Factory.build`'s `expose_return_as` canonicalize the same way, so `on: "address.billing"` and `on: :"address.billing"` are one route.
* [BREAKING] Every option that carries a name — a field name, `on:`, `as:`, `prefix:`, `expose_return_as:` — must be a String or Symbol, written in an ASCII-compatible encoding, and raises `ArgumentError` at declaration naming the option and the offending class otherwise (`on: must be a String or Symbol naming a parent reader (got a value of class Array)`). Previously an arbitrary object was accepted and anchored under whatever it rendered as: `prefix: []` generated a reader called `:"[]field"`. A String that has redefined `to_s` is refused for the same reason — a name has to mean one property. `as:`/`prefix:` now read `false`, `""`, a whitespace-only String and `:""` as "no rename", as `nil` already did; a field name is never optional, so `expects nil` and `expects false` raise.
* [FEAT] `expects … on:` (subfields) supports the full top-level option surface — `default:`, `preprocess:`, `coerce:`, `sensitive:`, `shape:`, and `user_facing:` — at any nesting depth. Subfields nest arbitrarily deep, and a dotted `on:` pulls a value out of a deeply-nested structure in one line: `expects :zip, on: "address.billing"` validates `address[:billing][:zip]` and defines a flat `zip` reader.
* [BREAKING] Dotted field names are removed. Use a dotted `on:` for nested extraction (`expects :zip, on: "address.billing"`, not `expects "billing.zip", on: :address`). To read two values from the same wire key, disambiguate the distinct routes with `as:`.
* [BREAKING] All subfield `coerce:`/`preprocess:`/`default:` resolve on the read path, and axn never materializes or mutates the parent to apply them. A subfield transform is visible through its own reader and its validation, but the parent reader returns exactly what the caller passed — `expects :note, on: :payload, default: "d"` with `payload: nil` leaves `payload` `nil` and `note` `"d"`. A subfield `default:` no longer satisfies the parent's own presence check, and a caller-supplied object is never written through its setter during validation.
* [BREAKING] Reading a subfield by method dispatch requires `method_call: true`. The safe default reads declared data only — Hash keys and `Struct`/`OpenStruct`/`Data` members. Reaching a value that can only be resolved by invoking a method (a plain object's reader, an `Array` method, a resolved `model:` record's attribute) needs `method_call: true` on that declaration; without it axn raises `MethodCallNotPermittedError` rather than silently invoking the method during validation. The same rule applies to shape members.
* [FEAT] A subfield whose parent is omitted or `nil` is treated as "subfields absent" — each subfield's own rule applies against `nil` (optional passes, required fails cleanly with `InboundValidationError`) instead of raising. An all-optional nested structure can simply be omitted.
* [BREAKING] Several unsatisfiable contracts now raise at class definition instead of failing on every call: a subfield path no contract-valid input could answer; a nil-tolerant field with an unrescued required descendant; two `default:`s on one merged wire node; and a `model:` batch that also names its own `<field>_id`. Each error names the offending declarations and the fix.
* [BREAKING] Two declared names that render as the same JSON property no longer both stand — the pair collapses onto one property, which used to silently emit a duplicate in `input_schema` or drop an exposure on the way out. Two field names, two `exposes` names, and two subfields under one parent raise at class definition; two shape members, a `model:`-generated `<field>_id` against a differently-spelled explicit one, a structured type's members against a shape's, and two routes only resolution equates raise when the projection is first built (and at app setup for tool axns). One wire slot named twice by the same spelling is a merge, stays legal, and emits one property. Details: [Names that one JSON property can't keep apart](https://teamshares.github.io/axn/reference/class#property-name-rules).
* [BREAKING] A declared name with no UTF-8 rendering is rejected, since `JSON.generate` refuses such a property name outright. An `exposes` name raises at class definition; a top-level `expects` name, a subfield, or a shape member raises when the contract's JSON projection is first built (`input_schema`, `output_schema`, `Axn::Extensions::Serialization.render`), and at app setup for tool axns. Judged on the names a schema actually emits, so a name it never emits is not rejected.
* [BREAKING] A contract whose reflected schema would name more than 25,000 JSON properties is rejected when that projection is first built, and a `shape:` graph with more than 25,000 member paths is rejected at class definition. A nested shape shared between sibling members multiplies out (N levels of two-way sharing are 2^N paths), and every walk of a stored graph pays one step per path. The schema bound counts one emitted property path, derived from the emitter's own decisions, so anything the schema names nowhere costs nothing.
* [FEAT] A failing call collects every violation across top-level fields, subfields, and model consistency and reports them together, and each nested-subfield failure names the stranding hop (`'payload.address' is nil, so nested expectations beneath it cannot be satisfied`).
* [BREAKING] `readers:` is removed — every declared field generates a reader. Use `as:`/`prefix:` to rename a colliding one.
* [FEAT] `as:`/`prefix:` rename a field's generated reader independently of the wire key (`expects :channel, as: :raw_channel`), freeing the name for your own method; `prefix:` renames several subfields at once (`prefix: :event_`).

### Validation, coercion & schema

* [FEAT] `coerce:` parses an inbound wire string into a field's declared Ruby type before validation, so a JSON or form client sending `"2026-07-08"` or `"123"` is accepted for a `Date`/`Integer` field. Coercible types are `Date`, `DateTime`, `Time`, `Symbol`, `Integer`, `Float`, and `:boolean`. Opt-in per field and coerce-or-leave: a real Ruby value passes through, an unparseable string fails validation normally ("could not be coerced to a Date"). No effect on `input_schema`/`output_schema`.
* [FEAT] `coerce_input_types` (a per-class-overridable config setting) turns on `coerce:` for every coercible top-level field and subfield — for a fully transport-facing action such as a controller handing it a params hash, or an adapter decoding JSON — without annotating each field. A field's own `coerce:` always wins.
* [FEAT] Tolerance flags combine with a scalar validator value: `expects :num, numericality: true, optional: true` (and likewise `inclusion:`/`format:` under `optional:`/`allow_nil:`/`allow_blank:`) work instead of raising a `TypeError`.
* [FEAT] Conditional validation: `expects`/`exposes` and shape members accept `if:`/`unless:`. The condition gates every validator including the implicit presence check, so requiredness itself can be conditional — expressing the conditionally-required-subfield pattern (`expects :user, on: :data, if: -> { data.present? }`). `error`/`success` and the `on_*` callbacks also accept `if:` and `unless:` together, combined with AND.
* [FEAT] `MyAxn.input_schema` / `MyAxn.output_schema` return JSON Schema derived from `expects`/`exposes` (subfields, `model:`, `of:`, `shape:`, `inclusion:`, defaults, unions), and `Axn::Extensions::Serialization.render(result)` renders a `Result` to a JSON-safe Hash — one definition an adapter can turn into an MCP `inputSchema`, an LLM `parameters` block, or an OpenAPI schema. Read-only and off the execution path; `sensitive:` has no effect on schema output.
* [FEAT] `allow_empty:` declares the emptiness axis independently of nullability, so all four requiredness contracts are expressible: `allow_empty: true` keeps a field required and non-nil while accepting an empty collection or string, and `optional: true, allow_empty: false` accepts an omitted or nil value while rejecting an empty one (which used to raise at declaration). It requires a `type:` whose values can be empty — `Array`/`Hash`/`Set`/`String`/`:params`, or any class defining `empty?` — and accepts only `true`/`false`/`nil`, so `allow_empty: "false"` raises rather than reading as truthy. Emptiness is `empty?`, not `blank?`. Where a declaration answers the emptiness question two ways — a `presence:` that disagrees, or a `length:` that explicitly admits an empty value — it raises at declaration naming both spellings instead of letting one win silently.
* [BUGFIX] A field that rejects empty values reflects that into `input_schema`/`output_schema` as `minItems`/`minProperties`/`minLength`, reading every `length:` spelling ActiveModel resolves into a floor. Previously a required `type: Array` rejected `[]` at runtime while its schema advertised `[]` as acceptable. Emission derives from the property's final emitted type, covers union `anyOf` branches and `output_schema`, and is withheld wherever an empty value can pass the validator set as a whole.
* [BUGFIX] A bare-Array `inclusion:` shorthand (`inclusion: %w[a b c]`) reflects into `input_schema`/`output_schema` identically to the `{ in: [...] }` long form — emitting the `enum`, inferring the member type, and contributing its nil-membership to the field's nullability. Previously the bare form validated at runtime but reflected as an unconstrained `{}`.
* [BUGFIX] A field's `optional?` and its schema requiredness answer one shared question ("do this field's validators accept nil?"). A field that rejects nil by type alone — most visibly a bare `type: :boolean` or `type: :params`, which skips the default presence injection — used to report `optional? == true` while both the schema and the runtime treated it as required. A field carrying a usable literal `default:` still reports `optional? == false` while the schema omits it from `required`: the two now agree on nil-tolerance specifically, not on every input to omissibility.
* [BUGFIX] An option bag keyed by strings — what a params-derived Hash or `.with_indifferent_access` produces — validates as declared. Bag keys are axn's own grammar (`klass:`, `in:`, `with:`, `minimum:`) and every consumer reads them as Symbols, so a String-keyed bag answered nobody: `type:`, `inclusion:` and `length:` declared cleanly and then rejected the values they were declared to accept, `model:` resolved a class inferred from the field name rather than the one declared, and `of:` raised "must supply :klass". Keys are canonicalized at declaration (a bag naming one option under both spellings is rejected rather than silently dropping one); values are untouched. A String key on the declaration itself (`expects :a, "type" => String`) is still an unknown key, as before.
* [BUGFIX] A `nil` rejected by a field's `type:` produces that one error instead of also running every other validator against the nil, so a custom `validate:` written for a real value no longer adds a derivative "failed validation" message.

### Shape blocks

* [FEAT] `shape:` declares the structure of a value you already hold — an array's elements, or a hash/object passed through as one unit — without defining readers: `expects :items, type: Array do field :sku, type: String end`. Members take validations, `optional:`/`allow_blank:`/`allow_nil:`/`allow_empty:`, `sensitive:`, `user_facing:` (`expects` only), `method_call:`, `if:`/`unless:`, and `description`, all with the same semantics as a top-level field, and recurse to any depth. Members are validation- and schema-only, so `default:`, `preprocess:`, `model:` and `coerce:` are rejected at declaration — declare an `expects … on:` subfield when you need a value resolved. Documented at [Describing the shape of structured fields](https://teamshares.github.io/axn/reference/class#shape-blocks).
* [BREAKING] The raw Hash form (`shape: { members: [...] }`) is held to its grammar at class definition rather than failing on every call. `members:` is required (an explicitly empty list stays legal); each member must answer both `#field` and `#validations`, and nothing beyond them, so a member implementing only those two reflects instead of raising `NoMethodError` from `input_schema`; a member name must be a String or Symbol and is stored as a Symbol; validator shorthands are expanded exactly as a field's, so `type: Hash` and `of: Hash` now work instead of raising `must supply :klass` (or taking `input_schema` down) per call; the `of:` guards a field gets apply, so `of:` beside a non-Array `type:` raises; a `container:` must be a class or module and is derived from `type:` at every nesting depth; and unknown or field-only keys (`optional:`, `default:`, `preprocess:`, `as:`, `prefix:`, `sensitive:`, `coerce:`, a `tpye:` typo) raise with a message naming the member and where a member's options actually live. Every check applies at every nesting depth.
* [BREAKING] Option containers you pass — `of:`/`validate:`/`inclusion:`/`exclusion:`/`type:` on a field, and a raw member's own bags and nested shapes — are deep-copied at declaration, so a builder Hash reused across two declarations, or a nested shape mutated afterwards, can no longer change an already-declared contract. Two containers are refused instead of copied, because a copy would silently become a different contract: an Array subclass defining methods of its own (most obviously its own `include?`) must be frozen or replaced with a plain Array, and a Hash answering missing keys from a `default`/`default_proc` (`type: Hash.new(String)`) is rejected outright. A frozen container is stored as-is with no copy; a plain Array, and a non-Array membership container (`Set`, `Range`, your own `include?`), are unaffected.
* [BREAKING] Two members under one parent — or two top-level members of one shape — may not share a name (rejected at class definition), nor carry two names that render as the same JSON property (rejected when the projection is first built). Members of different parent blocks never collide even at the same depth. Declaring the same member twice used to keep only the last in the reflected schema with no signal.
* [BREAKING] An untraversable `shape:` graph raises `ArgumentError` at class definition instead of overflowing the stack: a graph reachable from inside itself is reported against the member that closes the loop, and one that mints a fresh nested shape per read is rejected past 64 levels of nesting. The depth bound is judged over the graph you declare, not the route the walk happens to take, so a depth assembled out of shared sub-shapes is caught. Runtime walks over a stored graph are bounded too, and report an `ArgumentError` on the result rather than a `SystemStackError` carrying none of the contract.
* [BUGFIX] A member's `sensitive:`, name, `validations`, `metadata`, `user_facing:`, `method_call:` and `description` are read once at declaration into axn's own `ShapeConfig`, so every layer sees one canonical form. Previously a member object was stored live and different layers could disagree: flipping `sensitive:` after declaring took effect or not depending only on whether anything had asked yet, a member declared with String keys (what a params-derived or `with_indifferent_access` Hash gives you) reflected as an unconstrained `{}` while every call raised `must supply :klass`, and an Array subclass answering `each` differently from `filter_map` dropped a `sensitive:` member from the redaction set entirely. `output_schema` also no longer raises `NoMethodError: undefined method 'with'` for an `exposes` member carrying a per-validator `if:`/`unless:` gate.
* [BREAKING] A raw member's `#default` reader is no longer read. `default:` is not part of the member grammar, but a duck-typed member defining the reader had it emitted into the reflected schema, which then advertised the member as optional-with-a-default while the omitted call failed presence validation. Such a member reflects as required with no `default`. `#description` is still honored, from the reader or from `metadata`.
* [BUGFIX] A declared name whose bytes are not UTF-8 (a valid ISO-8859-1 Symbol) no longer breaks the messages and schemas that name it. Every layer that writes a name into prose renders it as the JSON property it canonicalizes to, so a validation error naming members in two encodings is readable (`.message` itself used to raise `Encoding::CompatibilityError`, taking any handler logging `e.message` with it), the nil-tolerance contradiction error reports, the call logger keeps its line, and `input_schema` no longer raises over a dropped deep subfield the warning only mentions in passing. A foreign class name renders on the same terms. The property-name rules likewise compare and render names without running code the name's author wrote, and the reflected schema's `required` list can no longer name a property its own `properties` map does not define.

### `model:` fields

* [FEAT] A `model:` field also defines a `<field>_id` reader returning the record's primary key, whether the action was called with `user:` or `user_id:`. It's alias-aware and triggers no extra lookup.
* [BREAKING] Passing both a `model:` record and a contradictory `<field>_id` (default `:find` finder) raises `InboundValidationError` instead of silently preferring the record. Passing one, or both in agreement, is unchanged.
* [FEAT] A `model:` field's record lookup consumes the read-path-transformed `<field>_id`: when a sibling `<field>_id` declares `coerce:`/`preprocess:`/`default:`, the finder sees the transformed id, so an id-only input resolves the same record the `<field>_id` reader reports.
* [BREAKING] `coerce:`/`preprocess:` on a `model:` field or subfield raise at declaration — a model field resolves a record, not a scalar wire value. Transform the `<field>_id` field instead.
* [BREAKING] `model:` record and key reads route through the canonical reader path (dispatching the reader method for object sources, indifferent to string/symbol keys for Hash sources), unifying model resolution with every other reader.

### `ambient_context`

* [FEAT] `ambient_context` is a reserved, always-present parent for ambient caller identity (`current_user`, `company`, …). Declare `expects :company, on: :ambient_context` and read `company` through the full validator stack; the parent is excluded from `input_schema` (so a client or LLM can never supply it) and only declared subfields get readers. Per invocation the value comes from an explicit `ambient_context:` kwarg, else `Axn.config.ambient_context_provider`, else a view over the registered `ActiveSupport::CurrentAttributes`, then filtered to the declared keys. It does not cross the `call_async` boundary.
* [FEAT] Ambient subfields support `default:`/`preprocess:`/`coerce:`/`sensitive:` and a leaf `shape:`, and nest to any depth — a dotted `on: "ambient_context.request"` or a subfield under an ambient subfield. The filtered hash is reconstructed along each declared path, so an undeclared sibling at any depth never reaches the resolved value, logs, or exception context. `user_facing:` stays rejected (an ambient value is framework-supplied, so there is no caller to face).
* [BREAKING] Exception reports carry the declared, sensitive-filtered `ambient_context` instead of the raw global `::Current.attributes`, replacing the reserved `current_attributes` context key with `ambient_context`. Breaking for any error-tracker rule, `on_exception` handler, or spec keyed on the old key.
* [FEAT] `with_ambient_context(**attrs)` test helper (auto-included into RSpec) injects ambient inputs for a block across the whole call chain — the action under test and any nested calls — restoring the provider afterward. An opt-in `Axn/AmbientContextBypass` RuboCop cop flags direct `Current.<attr>` reads inside actions.

### Failures & messages

* [FEAT] A declared base `error "…"` composes with an action's failure reasons: a conditional `error … if:`/`unless:`, a `fail!` message, or an entry marked `standalone: false` renders as `"<base>: <reason>"`. An unconditional entry is the base headline; conditionality sets the role, overridable with `standalone:`. `join:` on the base controls the separator (a String, or a `->(base, reason) {}` Proc). `success`/`done!` mirror this. `result.error` returns the composed string, and for axn-owned failures the raised exception's `#message` is stamped to match.
* [FEAT] `fails_on` reclassifies chosen exception classes from the exception outcome into the failure outcome — firing `on_failure`, skipping the global `on_exception` report, and keeping the original exception on `result.exception`. It accepts a message, a block, an array of classes, and `standalone:`. Classification is sticky to the exception object and flows outward only, so declare it on the action that raises. `result.error` never defaults to the exception's own `#message`; opt in with `fails_on Klass, &:message` when the message is genuinely user-facing.
* [BREAKING] `fails_on` raises `ArgumentError` at class definition when given an exception axn never converts into a result — a signal, an `exit`, `NoMemoryError`, or a library's own control-flow signal, all raised straight through `.call`. The declaration would have been silently inert. `fails_on Exception` is still accepted; only a class with no reachable exception anywhere in its hierarchy is rejected.
* [FEAT] `user_facing:` marks an `expects` field whose violation is the caller's fault, reclassifying it from the exception bucket into the failure bucket (fires `on_failure`, skips the global report, surfaces the field's validation message on `result.error`). The value rides `fail!` muscle memory — `true`, a String, a Symbol, or a callable. The field stays required. It composes at every declaration depth including shape members; in a mixed failure any dev-facing field still dominates, so a real contract bug is never masked. Rejected on `exposes` and on ambient subfields.
* [BUGFIX] `SystemStackError` and `ScriptError` (so `NotImplementedError`/`LoadError`/`SyntaxError`) are treated as the bugs they are instead of escaping unnoticed. Either settles as an `exception` outcome that `call` returns, with `on_error`/`on_exception` firing and the global handler notified once at the innermost action; `call!` raises it unwrapped as always. Previously nothing rescued these, so the run settled as nothing at all — `outcome` read `success`, the global report never fired, and a user's own runaway recursion was invisible to error tracking. A `validate:` callable is the deliberate exception: its own guard converts any raise into that field's validation message. Every other exception outside `StandardError` still passes straight through untouched (signals, `exit`, `NoMemoryError`, `Timeout::ExitException`, a library's private control-flow signal).
* [BREAKING] A nested `call!` failure re-raises the inner action's original exception — previously a fresh `Axn::Failure` wrapping it, with a `source:` pointer, both removed — so `Axn::Failure` now means exactly "`fail!` was called". A nested `call!` aggregates every level's declared base header (`"Outer: Inner: leaf"`), and an unhandled exception is reported to the global `on_exception` once, at the innermost executor. To reshape a child's error, run it with non-bang `call` and re-`fail!`; to branch on a failure, match the exception type or `result.exception` rather than the message string.
* [BREAKING] `error from:` and the per-message `prefix:` option on `error`/`success` are removed. Use a declared base `error "…"` and the `call` + `fail!` idiom for cross-action message shaping.
* [BREAKING] Removed the experimental `_include_retry_command_in_exceptions` setting and its `retry_command` exception-context key — it embedded field values into a single command string that defeated key-based redaction in error trackers. Use the structured `inputs`/`outputs` context, whose per-key filtering is intact.
* [BREAKING] Actions can no longer be instantiated directly — `new` is a private class method. Use `.call`/`.call!`; a test needing a bare instance can `.send(:new, …)`.
* [BUGFIX] A failure in a side channel can no longer replace the exception in flight. `Axn::Extensions.best_effort` — called from `ensure` blocks throughout the executor — built its warning out of the exception it had just caught, so an exception whose `#message` raised, or whose message carried non-ASCII bytes in an encoding other than UTF-8, escaped through the guard meant to contain it: `expects :n, validate: ->(_v) { raise … }` lost the caller's `InboundValidationError` entirely and reported the guard's own failure. Every message axn composes now renders all of its own operands rather than some — a `join:` separator, a declared field name, a foreign exception message or class name, a `path:`/`reason:` — since a rendered UTF-8 half beside a raw Latin-1 one is what raises. `best_effort` can now only raise the exception its block raised, or an axn-owned `Axn::ReraiseFailed` carrying it as `cause` where Ruby's `raise` cannot hand that object back as itself. Eleven further sites that write a foreign exception into prose are covered on the same terms.
* [BUGFIX] `Result#inspect` no longer raises on a result that is intact underneath. On a failed result it asked `default_message?` — axn's own predicate on `Axn::Failure` — of an exception that was not one, so the everyday `fails_on` and `user_facing:` routes got a bare `NoMethodError`; on a successful one it joined a declared name to a value's `inspect` with neither rendered, and a value whose own `inspect` raised escaped through it. Outside Rails it also raised `NoMethodError: undefined method 'to_fs'` for a plain `Date` exposure; dates now prefer `to_fs` only where the value answers it (honoring an app's registered `Date::DATE_FORMATS[:inspect]`) and otherwise fall back to axn's own ISO-8601 rendering. `[FILTERED]` and every ordinary `inspect` are unchanged.
* [BREAKING] Whether a `fail!` reason or a message handler's return value counts as "no reason given" is decided from the value's class and its own bytes rather than by dispatching the object's `blank?`, so a `fail!(obj)` whose object cannot answer that no longer takes down `result.error`, the `on_error` callbacks and the failure classification with it. The narrowing: an empty container is now a reason. `fail!([])`, `fail!({})`, `fail!(Set.new)`, and `error -> { {} }` / `success -> { some_empty_hash }` render that object as the message instead of falling back to the default. A handler returning `""`, `nil`, `false` or `0` is unchanged.

### Steps

* [FEAT] `step` accepts `if:`/`unless:` (a Proc `instance_exec`'d on the parent, or a Symbol naming a parent method, combinable), evaluated immediately before the step would run. A skipped step exposes nothing and cannot fail; later steps still run.
* [BREAKING] A step that raises an unexpected exception settles the parent as an exception (fires `on_exception`/`on_error`, not `on_failure`), while a deliberate `fail!` or a `fails_on`-classified exception still settles the parent as a failure with the composed message. Declaring steps and a custom `#call` on the same class raises `ArgumentError` at load time.

### Async

* [BREAKING] The Sidekiq adapter no longer turns the action into a `Sidekiq::Job`. A generic worker runs every action by name, so `MyAction.perform_async`/`sidekiq_options`/`.set`, and Sidekiq's class-level testing helpers (`.jobs`/`.drain`/`.perform_one`), are gone from the action — use `call_async`. Per-action config is unchanged in spelling (`async :sidekiq, queue: "x", retry: 3` and the block form), now applied to a per-action worker subclass. The Web UI still shows the real action name. Verified on Sidekiq 7 and 8.
* [FEAT] Async argument serialization uses `ActiveJob::Arguments` whenever ActiveJob is loaded (for all adapters, including Sidekiq), so GlobalID models, `Date`/`Time`/`DateTime`, `Symbol`, `Range`, `BigDecimal`, and nested symbol-keyed hashes round-trip losslessly — fixing a Sidekiq-enqueued `expects :at, type: Time` that used to arrive as a `String`. A deployment without ActiveJob accepts only JSON-native and GlobalID-able args.
* [BREAKING] Enqueuing an async action with an unserializable argument raises a field-aware `Axn::Async::UnserializableArgument` at enqueue time instead of silently corrupting it. The Sidekiq wire format changed to ActiveJob's `_aj_*` tagging for rich types — drain the queue across the deploy.
* [FEAT] `Axn::Async.owns?(candidate)` answers "is this job/notice signal Axn-owned?" for error-reporter `before_notify`-style filters that suppress duplicate backend-native reports; it accepts a Class, a class-name String, or a raw Sidekiq job Hash. `Axn::Async.register_ownership_predicate` lets an adapter extend detection.
* [FEAT] axn's per-execution state (the nesting stack, exception classification) lives in `ActiveSupport::IsolatedExecutionState`, so it isolates correctly under a fiber-based host once `isolation_level = :fiber` is set. Because axn can't set that itself, a process running a `Fiber.scheduler` under the default `:thread` isolation gets one warning naming the fix instead of silently sharing state across concurrent fibers. Documented at `/advanced/concurrency`.

### Logging & observability

* [BREAKING] `log_calls` and `log_errors` are replaced by a single declarative `auto_log` that resolves a level (or off) per outcome — `success`, `failure`, `exception`. A positional level is the default for any unnamed outcome; keyword overrides target one outcome, so `auto_log exception: :error` logs only raised exceptions, distinguishing an unhandled raise from an expected `fail!`. Migration: `log_calls <lvl>` → `auto_log <lvl>`; `log_calls false` → `auto_log false`; `log_calls false` + `log_errors <lvl>` → `auto_log <lvl>, success: false`.
* [FEAT] `tag` (high-cardinality) and `dimension` (bounded) declare per-action observability facets, resolved from inputs before the body (`from: :inputs`) or from the settled result (`from: :result`). Each facet flows to the `axn.call` OpenTelemetry span, the notification payload, `emit_metrics`, `auto_log` output (as SemanticLogger tags, or a readable suffix under any other logger), the `on_exception` report (`context[:tags]`/`context[:dimensions]`, now reserved keys), and Sidekiq per-job tags (selected by `Axn.config.sidekiq_job_tag_sources`, per-class overridable).
* [BREAKING] `on_success` fires after the enclosing transaction commits (immediately when none is open) and is skipped on rollback, so an action nested inside another's transaction no longer fires its side effect when the outer transaction later rolls back. Implemented via `ActiveRecord.after_all_transactions_commit` (requires ActiveRecord 7.2+; inline without ActiveRecord). Failure-path callbacks are unaffected.
* [FEAT] `on_enqueue_all` is a once-per-run callback for `enqueues_each`/`enqueue_all` fan-out, firing after the loop completes with the enqueued `count:` and a `sources:` hash (flexible arity). It's error-isolated, so a raising callback can't abort the fan-out.
* [BREAKING] `sensitive:` accepts only what it can resolve — `true`, `false`, `nil` (so `sensitive: some_flag` reads naturally), a Symbol naming an action method, or a Proc — and rejects anything else at class definition, wherever `sensitive:` is accepted: a field, an `exposes`, an `on:`/ambient subfield, and a shape member. **Audit existing declarations:** any other value was previously accepted silently and redacted **nothing**, so `sensitive: 1` or `sensitive: "yes"` reads like an opt-in and logged the field in the clear. A non-Proc callable is rejected too — it would be truthiness-tested, not called. `user_facing:` is held to its own grammar on the same terms, on a field and on a shape member; a truthy non-rule used to reclassify the violation and surface the literal `"123"` to the caller.
* [BUGFIX] A field or shape member declared `sensitive:` after the class had already logged a call is redacted. The name-based filter was memoized on first use with no way to notice a later declaration, so reopening a class (or a `Mountable` builder rewriting its contract) left the new secret logged in the clear for the life of the process. Every fact redaction derives from the declaration is now keyed on the identity of the field-config arrays, which any declaration replaces.
* [BUGFIX] Redaction no longer walks the whole declared `shape:` graph on every logged call — everything decidable from the declaration is decided once per class, so a logged call's cost is independent of the graph's size: a 24,000-member shape went from ~34ms per logged call (and ~23ms per `inspect`) to under 0.01ms. Worst hit before were contracts using no `sensitive:` at all, since concluding "there is nothing to redact" is what requires visiting every member. A `sensitive:` given a Proc or Symbol still resolves per call against the action.
* [BUGFIX] A self-referential (cyclic) Array or Hash no longer crashes `.call` with `SystemStackError`. Every walker that formats caller-supplied values for observability — the call logger, exception-report context, facet coercion, sensitive-member masking — cycle-guards its recursion the way Ruby's own `#inspect` does, rendering `[...]`/`{...}` for a container already open on the path (one merely repeated among siblings still renders in full). `ActiveSupport::ParameterFilter`, which any `sensitive:` declaration puts in the path and axn cannot guard from inside, is handled by retrying the slice on a decycled copy, and an `ActionController::Parameters` input holding a cyclic value falls back to a `{...}` placeholder for that one value rather than costing the whole log line and `on_exception` report. Acyclic data pays nothing for the fallback.
* [BUGFIX] Rendering a result through `Axn::Extensions::Serialization.render` raises the new `Axn::Extensions::Serialization::UnserializableValue` for a self-referential exposed value instead of recursing to `SystemStackError` — and being an `ArgumentError`, a serving adapter's existing `rescue StandardError` maps it to an error response. The message names the path to the offending value (`items[1]`, `node.child`), and the guard tracks ancestry, so the same object referenced twice as siblings is not a false positive. Enqueuing one raises the normal `Axn::Async::UnserializableArgument` naming the field, rather than a `SystemStackError` escaping the enqueue.
* [BUGFIX] `auto_log`'s completion line is skipped when the run never settled, instead of reporting `Execution completed (with outcome: success)` for an action that never started and raising `NoMethodError` while formatting a nil duration. That raise came out of an `ensure` and replaced the in-flight exception — silently destroying an enclosing `Timeout.timeout` and turning a Ctrl-C on the inbound line into an unrelated `NoMethodError`. Both `auto_log` hooks are now guarded as a whole rather than only at the emit: everything used to build a line (the duration, the facet maps, the separator, the context slices) was an argument to the guard and so evaluated outside it.
* [BUGFIX] Swept the remaining guards that promised "never raises" but only rescued `StandardError`, so each now covers everything axn absorbs: a `join:` callable, a `validate:` callable (which still fails the field, message and all), a raising `if:`/`unless:` matcher (warned and simply not matching, rather than rewriting the action's outcome), `enqueues_each`'s filter block, `via:` extraction and per-item progress read, the `on_enqueue_all` callback, and the memoized `ambient_context` provider error. Two of those were worse than a lost warning: an escape from `join:` skipped `on_error`/`on_failure`/`on_exception` and then raised again on every later `result.error` read, and an escape from the fan-out failed the orchestrator job with the batch already partly enqueued, so the queue's retry enqueued it again. The best-effort guard's own warning emission can no longer raise either — it frequently runs from an `ensure`, so a logging backend that cannot write would have replaced the exception already in flight.
* [BUGFIX] Files that reference another file's constant at runtime now require it, instead of relying on the top-level `axn` entrypoint's require order. Loading `axn/internal/reflection` on its own and serializing any Hash or Array raised `NameError`; the same latent gap existed in the call logger, exception-report formatting, facet coercion, async serialization, `FormObject`, the property-name rules, the schema builder, the shape-graph reader and the field-name conventions. The contract is now derived from each file's own parse tree rather than a hand-maintained list.

### Configuration

* [FEAT] `Axn::Configurable` is a small DSL for gems built on Axn to declare validated configuration — `setting` with `default:`/`one_of:`/`validate:` and a `<name>?` predicate — instead of hand-rolling a config object, `configure` yielder, and test reset. A Proc `default:` is dynamic: re-derived on every read while the setting is unset and never cached, so a default that depends on host-app boot state stays correct even when that state arrives after the gem loads. An assigned value — including a Proc, including `nil` — is always used as-is. `extend Axn::Configurable::Settings` declares the same validated settings as instance accessors on a plain class.
* [FEAT] Settings declared `overridable: true` gain per-class overrides on actions: `MyAction.configure { |c| c.setting = value }` resolves the nearest-ancestor override and falls back to the library default, inherits into subclasses, and never leaks to siblings or mutates `Axn.config`. Each also gets a `<name>?` predicate and a `<name>_override` reader (the stored override, or the `UNSET` sentinel with no fallback). Per-class config is namespaced — `configure(:mcp) { … }` — so an action composing several adapter mixins carries each adapter's overrides without collision.
* [BREAKING] `Axn::Configurable`'s `setting … callable: true` is removed; drop the keyword (`setting :x, default: -> { … }, callable: true` becomes `setting :x, default: -> { … }`, with identical behavior). Passing it raises `ArgumentError: unknown keyword: :callable` at class definition. Two real semantic changes come with it, in opposite directions: a Proc `default:` declared without the keyword used to be returned as the Proc itself and is now invoked on every unset read, and an assigned Proc used to be called on read and is now returned as-is.
* [FEAT] A `validate:` callable may return a truthy String instead of `true` to reject a value while explaining why: the assignment still raises `ArgumentError`, with the String appended as the reason (`"<name> got invalid value: <value> — <reason>"`). Returning `false`/`nil` still raises the generic message alone.
* [FEAT] `config.reset!(:setting)` (and `reset!` with no arguments) returns settings to their declared defaults — the supported alternative to assigning `nil`, which is a value rather than a reset. Available on every `Axn::Configurable` config, including an adapter gem's own, and on `Axn.config`. `reset!` is reserved as a setting name in consequence; the name never worked anyway (it raised `NameError` on the first read), so the failure just moves to the declaration.
* [FEAT] `Axn.config.tracer` supplies or disables the tracer that receives axn's `axn.call` spans. Unset auto-detects (the OpenTelemetry tracer when OpenTelemetry is loaded, no spans otherwise); an object receives spans whether or not OpenTelemetry is loaded; `nil` turns axn's spans off without unloading OpenTelemetry. Spans are gated on a tracer being present rather than on `OpenTelemetry` being defined, and a non-OpenTelemetry tracer receives the full span — attributes, facets, `record_exception` — everything but an error `Status`, which only OpenTelemetry can construct. The whole tracing path is best-effort: a tracer that raises, or an `in_span` that never yields or yields twice, cannot change the fact that the action runs exactly once and its settled result is what `.call` returns — except under `best_effort_raises_in_dev`, which re-raises the tracing failure on purpose after the action has run.
* [FEAT] `Axn.config.default_async?` answers whether a default async adapter is configured, so a gem asking only "is async on?" has a public predicate instead of testing the underscored `_default_async_adapter` for presence.
* [BUGFIX] `Axn.config.env` is validated at assignment, so a value the reader cannot use is rejected on the line that sets it rather than raising `TypeError` from every later read (six sites inside the gem plus every `Axn.config.env.production?` in user code), which meant an initializer's typo detonated on the first action to run, nowhere near its cause. A Symbol is coerced, a String (including a subclass, which is what `c.env = Rails.env` assigns) is stored as it stands, `nil` clears the override and restores auto-detection from `RACK_ENV`/`RAILS_ENV`, and anything else raises an `ArgumentError` naming the option and the offending value's class.

### Tools & adapters

* [FEAT] The tool surface lives on `Axn::Tools`: `Axn::Tools.for(:adapter)` enumerates an adapter's tools (`all_versions:` for every version), `Axn::Tools.versions(:adapter, tool_name)` returns one tool's version group, `Axn::Tools.register_adapter(:key, self)` registers an adapter, `Axn::Tools.adapters` lists the registered keys, and `Axn::Tools.validate_contracts!` validates every tool axn's contract at setup. Tool-specific errors live there too (`Axn::Tools::InvalidContract`). The top-level `Axn` module holds only `config`, `configure`, and `included`. Two more things a gem building on axn reaches for are `Axn::Extensions.owned_failure?(exception)` and `Axn::Extensions::Serialization::UnserializableValue`.
* [FEAT] Tool support: every Axn derives one provider-safe `tool_name` (mirroring an explicit `axn_name`, else derived from the class name), and a `tool` class-DSL declares registry membership — `tool` (every registered adapter), `tool :mcp, :ruby_llm` (an explicit set), `tool false` (opt out), `tool name: "…"` (override). `Axn::Tools.for(:mcp)` returns member classes in deterministic `tool_name` order. Membership is fail-safe: only classes explicitly marked, living under an adapter's `tool_roots` dir, or carrying a `configure(<adapter>)` bag are exposed.
* [FEAT] The `tool` DSL accepts per-adapter option bags — `tool mcp: { title: "Search", present_as: :message }, ruby_llm: { halt_after: true }` — as sugar over `configure(<adapter>)`: each key lands in the same per-class override store and resolves the same way, and a bag key implies membership in that adapter. `name:` inside a bag overrides the provider name for that adapter only (bare `tool name:` stays shared); a per-adapter name is honored by `Axn::Tools.for`'s ordering and duplicate detection.
* [FEAT] `tool_version N` declares a tool's contract version (a first-class core attribute, sibling of `tool_name`). Absent ⇒ version 1. Multiple versions of one logical tool coexist by sharing a `tool_name`; the registry identity is `(tool_name, tool_version)`. `Axn::Tools.for(adapter)` returns the latest version per name, `all_versions: true` enumerates every version, and `Axn::Tools.versions(adapter, tool_name)` returns a version group (`.all` ascending / `.latest`). When a class declares `tool_version` and its constant ends in a `::Vn` segment (`AgentTools::ApproveLoan::V2`), `tool_name` derives from the enclosing namespace so versions group under one name; a `::Vn` constant with no `tool_version`, or a mismatched number, raises.
* [FEAT] `Axn::Tools.validate_contracts!` validates every registered tool axn's contract in one pass and raises on the first invalid one, naming the offending class. Under Rails the engine calls it at `config.after_initialize` and on every `config.to_prepare`, so an invalid tool contract is a boot (or reload) failure rather than something a user's tool call discovers; without Rails an app calls it itself. What bounds coverage is documented on the method — at least one adapter must be registered, and a tool outside every configured root is only covered once something has loaded it. Everything not reached falls back to validating on first projection, which is where every non-tool axn is validated anyway.

An explicit `tool :openapi` now *adds* that adapter on top of the tool's directory grant instead of replacing it. `tool except: :ruby_llm` removes a single adapter; `tool false` still opts out of all.
* [BREAKING] The global `Axn.config.tool_paths` setting is removed. The same broad-path guard (`actions`/`app`/`.`/`..` rejected) applies. `Axn::Tools.register_adapter` takes an optional second argument — the adapter's own config source (`Axn::Tools.register_adapter(:mcp, self)`) — so the registry can read its `tool_roots`; adapters with no directory roots may omit it.

* [FEAT] Class-level `axn_name "…"` and `description "…"`, both inherited. `axn_name` is the single source of an action's display name across logging, the `axn.call` notification `resource` (the Datadog dimension), exception breadcrumbs, and profiling labels — so a factory-built or adapter-wrapped tool reports under one canonical identity. The async enqueue/constantize path still uses the real Ruby class name.

Class-level extension primitives (`Axn::Extensions.config.register_semantic_hint`, `Klass.set_extension_metadata` / `extension_metadata`) let an adapter hang transport-specific config off any Axn with no marker mixin.
* [FEAT] `Axn::Factory.build` accepts the full class-level DSL, so a factory-built Axn can declare everything a hand-written class can: `axn_name:`, `description:`, `semantic_hints:`, and the accumulating `fails_on:`/`tag:`/`dimension:` (each a single spec or a list). Documented at `/reference/factory`.

Rendering behavior, error messages, and `UnserializableValue` (which adapters rescue by name) are unchanged.
* [BREAKING] `Serialization.render` raises `UnserializableValue` for the values `JSON.generate` refuses outright, so what it returns is encodable JSON: a non-finite Float (or a `BigDecimal`/`Rational` that coerces to one), a String — or a Hash key's String form — whose bytes have no UTF-8 rendering, and two of a Hash's keys that render as the same JSON property (`{id: 1, "id" => 2}`, which used to collapse into one property and silently drop a value). This replaces a bare `JSON::GeneratorError` at the adapter's encode step, or a pathless generic 500, with a message that names the path (`records[3].price`) and the fix. A String valid in ISO-8859-1 or Shift_JIS transcodes cleanly and passes. Reflection is unaffected: a literal `default: Float::INFINITY` still reflects as declared.
* [FEAT] `Serialization.render` accepts `reject_opaque: true`, which additionally rejects an exposed value — or a Hash key — that declares no rendering of its own. The rule is where the rendering method is *defined*, not what it produces: the value's `to_s` is the one inherited from `Object`, or (in a Rails app, where ActiveSupport adds a generic `Object#as_json`) that generic method is its only `as_json` and it has neither `to_h` nor `to_hash`. So `"#<User:0x000055…>"` outside Rails and the instance-variable dump the same value produces inside Rails are both rejected, while a `Proc`, an `alias_method :to_s, :inspect`, or a delegator forwarding `to_s` all pass. Off by default: such output is complete, just not a shape the value's author declared, so an HTTP adapter can reject it while an LLM tool adapter keeps returning an ugly string instead of failing the call.

### Namespaces & extension API

* [FEAT] `Axn::Error` — a marker module included into every public exception class axn defines, so `rescue Axn::Error` catches one whichever superclass it descends from. It is not a blanket sweep over everything axn raises: a generic `ArgumentError` for DSL misuse stays a plain `ArgumentError` by design, and `Axn::Failure` is deliberately excluded (a control-flow signal from `call!`, not a fault). A gem building on axn roots its own hierarchy there: `class Axn::Webhooks::Error < StandardError; include Axn::Error; end`.
* [BREAKING] `Axn::DuplicateFieldError` is now `Axn::ContractViolation::DuplicateFieldError`, joining its eight siblings under the class it descends from.
* [BREAKING] `Axn::UnreraisableException` is now `Axn::ReraiseFailed`. The old name described the original exception — the one `raise` could not hand back — while the object it names is the substitute.
* [BREAKING] The six public registry errors (`Axn::StrategyNotFound`, `Axn::DuplicateStrategyError`, `Axn::Async::AdapterNotFound`, `Axn::Async::DuplicateAdapterError`, `Axn::Mountable::MountingTypeNotFound`, `Axn::Mountable::DuplicateMountingTypeError`) no longer descend from `Axn::Internal::Registry::{NotFound, DuplicateError}`. They are `StandardError`s carrying `Axn::Error`; use `rescue Axn::Error` for "any registry lookup miss".
* [BREAKING] The dev-loud/prod-quiet best-effort guard is now `Axn::Extensions.best_effort("intent") { … }` (block form) — the sanctioned surface for gems building on axn. `Axn::Internal::PipingError` is removed. Config knob `raise_piping_errors_in_dev` is renamed `best_effort_raises_in_dev`.
* [FEAT] `Axn::Extensions.best_effort` swallows `StandardError` plus `Axn::Extensions::SWALLOWABLE_BEYOND_STANDARD_ERROR` (`SystemStackError`, `ScriptError`), so a side channel — a log line, a span update, an error report — can never be what takes down the call it describes. That one allowlist is also what `Core::Executor` may settle onto a result, so there is a single answer to what axn will ever swallow, exposed as `Axn::Extensions.swallowable?`. It is an allowlist rather than a denylist because the non-`StandardError` set in a live process is open-ended, and several classes (`Timeout::ExitException`, `ActiveSupport::ErrorReporter::UnexpectedError`) exist precisely so nothing swallows them. `standard_errors_only: true` narrows a guard to `StandardError`; resolving a `model:` record is the one place in the library that qualifies, so a runaway finder surfaces as a reported exception result naming the real stack instead of a misleading "can't be blank".
* [BREAKING] The extension-config registry moved to the `Axn::Extensions` namespace: `Axn.extension_config` → `Axn::Extensions.config`, `Axn::ExtensionConfig` → `Axn::Extensions::Config` (methods like `register_semantic_hint` unchanged on the object).
* [BREAKING] Internal machinery moved out of the top-level `Axn::` namespace under `Axn::Core` (`Executor`, `Context`, `ContextFacade`, `ContextFacadeInspector`, `InternalContext`); public constants (`Result`, `Failure`, `Factory`, `FormObject`, `Configuration`, `Strategies`, the exception classes) stay top-level. Sibling gems own `Axn::<GemName>`; policy documented in AGENTS.md.
* [FEAT] `Axn::Testing.reset!` drops axn's process-global derived state (tracer auto-detection, the Sidekiq auto-configure validation memo, the one-time fiber-isolation warning) for a host app's spec suite. It deliberately leaves `Axn.config`, `Axn::Extensions.config`, the registries, `Tools::Registry`'s recorded action classes, its registered tool adapters, and the Sidekiq auto-configure registration flags alone — those record work that cannot be re-established or undone within the process, so clearing them would make the record lie.
* [INTERNAL] `Internal::Reflection` now holds only the three modules that derive a JSON view of a contract. `Coercion`, `SubfieldTree` and `ResolvedSubfields` moved to `Internal::`, and `SubfieldContradictions` to `Core::Contract::`. `Internal::SubfieldTree` is layer-free: its `ResolutionResult` is `roots`/`deep_paths`/`index` only, and the dropped-subfield judgment moved into `Reflection::Schema`. No public API impact.
* [INTERNAL] `_`-prefixed helpers that are only ever called internally are now private — 69 methods, across the modules extended onto every action class (`Contract`, `ContractForSubfields`, `Contract::Redaction`, `AmbientContext`, `ExtensionMetadata`, `Logging`) and axn's own modules and classes. Visibility only: every one was already reached with an implicit receiver, no call site changed, and no `send` was added to a runtime path. Two namespaces are where the leak reached outside axn — `Configurable` is extended onto a consuming gem's own namespace module, and the mounting strategies `extend self`. A downstream gem reaching a narrowed helper should move to the public counterpart beside it (`sensitive_fields` for `_static_sensitive_fields`, `expects … on:` for `_expects_subfields`).

## 0.1.0-alpha.4.3
* [FEAT] Plain namespace **modules** can now host mounted actions: `include Axn::Mountable` on a module (not just a class) exposes `mount_axn` / `mount_axn_method` / `step`. Class hosts keep the existing `class_attribute` + `inherited` behavior; module hosts use singleton accessors and skip the `inherited` hook (modules have no subclasses). Also fixes a `.name` clobber so passing an already-named class to `mount_axn` preserves its original name instead of rewriting it to the `Axns` namespace path.
* [BUGFIX] Fixed an off-by-one in `async.attempt` reported from the Sidekiq death handler: Sidekiq increments `retry_count` before invoking death handlers, so an exhausted `retry: 3` job (4 executions) reported attempt `5` instead of `4`. The bug was metadata-only — control flow (`retries_exhausted?`, `first_attempt?`, `should_trigger_on_exception?`) was unaffected. Also documents why framework-native integrations (e.g. Honeybadger's Sidekiq plugin) can produce duplicate async error reports, with a tag-and-filter suppression recipe.
* [BUGFIX] Subfield names that collide with a method on the parent value (e.g. `zip`, `count`, `first` — any `Hash`/`Enumerable` method) are now read as keys instead of being dispatched as method calls. Previously `expects :zip, on: :address` extracted `address.zip` (`Enumerable#zip`) and failed with a bogus error; `FieldResolvers::Extract` now digs the key first for Hash-like sources and only falls back to a reader method for non-diggable objects (e.g. `Data` instances).
* [FEAT] `expects … on:` now accepts a **dotted path** to reach a deeply-nested parent (e.g. `expects :zip, on: "address.billing", type: String` validates `address[:billing][:zip]` and defines a flat `zip` reader). The root segment must be a declared field/subfield. `default:`/`preprocess:`/`sensitive:` combined with a dotted `on:` raise `ArgumentError` (writing into — and redacting — an arbitrary nested path isn't supported yet); single-key `on:` is unchanged.
* [FEAT] Add block syntax for declaring the per-member shape of a structured field on `expects`/`exposes`. On a `type: Array`, `type: Hash`, or class-typed field, a block declares member contracts: `expects :items, type: Array do field :status, type: String, inclusion: { in: %w[a b] } end`. Members accept the same options as top-level fields (`type`, `inclusion`, `optional`, `description`, …) and recurse via nested blocks. For arrays each element is validated with indexed errors (`element at index 2: status …`); for a single Hash/object value its members are validated directly. The block requires a single structured `type:` (raises `ArgumentError` on scalars, unions, or no type), composes with `of:` (which still checks element class), and — unlike `on:` subfields — defines **no** reader methods. Downstream tooling reads members from `config.validations[:shape][:members]`.
* [FEAT] Add `of:` array-element validation for `expects`/`exposes`. On a `type: Array` field, `of:` validates each element: a single class (`of: String`), a union (`of: [String, Numeric]` — an element passes if it matches *any*), the `:boolean`/`:uuid`/`:params` symbols, or a `Data.define` class. Only valid alongside `type: Array` (raises `ArgumentError` otherwise, including for unions like `type: [Array, String]`). Error messages report the failing element's index (e.g. `element at index 2 is not a String`) and honor a custom `message:`. `optional`/`allow_blank`/`allow_nil` govern whether the whole field may be absent — they do not make individual elements blank-able. Downstream tooling can read the element type from `config.validations[:of][:klass]`.
* [FEAT] `exposes`-declared fields that are also `expects`-declared are now auto-copied from the input into the result on **all** outcome paths — success, `done!`, `fail!`, and unhandled exception. Previously, the auto-copy only ran on success/`done!` paths, leaving `result.field` as `nil` after `fail!` or an exception even when the field was provided as input. This is particularly useful for re-exposing mutated ActiveRecord objects (e.g. inspecting `user.errors` after a failed save). Explicit `expose` calls before a failure continue to work and take precedence.
* [FEAT] Execution log messages now display elapsed time in human-readable units (milliseconds, seconds, minutes, or hours) instead of always showing milliseconds
* [BREAKING] `exposes` no longer defines a direct reader method on the action instance. Exposed fields must be accessed via `result.field` (e.g., `result.greeting`). `expects` readers are unaffected. User-defined methods with the same name as an exposed field are preserved (DefaultCall still calls them). Use `result.field` in `success`/`error` message callables and `sensitive:` procs to access output values.
* [FEAT] Add boolean predicate readers for `expects` and `exposes`: `expects :enabled, type: :boolean` defines `enabled?` on the action instance; `exposes :enabled, type: :boolean` defines `result.enabled?`.
* [BUGFIX] `ExceptionContext.build` no longer raises `URI::GID::MissingModelIdError` when an exposed or expected value is an unpersisted ActiveRecord record. The formatter now renders such values as `#<ClassName (unpersisted)>` and the optional retry command falls back to `inspect` instead of generating `Model.find(nil)`.
* [FEAT] Add dynamic `sensitive:` option support for `expects` and `exposes` fields - accepts procs or symbols that are evaluated at runtime against the action instance, allowing conditional sensitivity based on input values (e.g., `exposes :data, sensitive: -> { redact_mode }`)
